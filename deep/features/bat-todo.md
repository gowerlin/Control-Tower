# 待辦分頁（BAT ↔ CT 契約 v2）

<p class="ct-lead">一句話：塔台要你做的事，從「終端裡的一段話」變成「檔案裡的一筆資料」。CT 把要你決定的事（<code>U-n</code>）和要你自己執行的事（<code>A-n</code>）寫進 <code>_tower-state.md</code> 的 frontmatter，BAT 的「待辦」分頁唯讀顯示；不用 BAT 的人也一樣，有東西在等你時，塔台每次回覆的最後一行都會重列一次。沒有東西在等你時，什麼都不多。</p>

v6.1.0 起屬正式版（6.1.0-pre.1 預覽時加入），已在 BAT 0.8.0-pre.3 的測試版上實機驗證。6.2.0 起加上[推薦項](#recommended)、[放棄與略過](#dismiss)、[暫停改開原生選單](#menu)與[提醒頻率 `pending_reminder`](#pending-reminder)（6.2.0-pre.1 預覽時加入、pre.2 依實機驗收修正），已在 BAT 0.8.0-pre.4 的測試版上實機驗證。本頁是摘要；確切的欄位、上限、回答寫法與訊息字樣以 CT `memory-protocol.md` § 契約 v2 欄位（含〈暫停的提問方式〉）與 `auto-session.md` § 塔台分頁角色宣告為準，提醒頻率以 `control-tower/SKILL.md` § Output Style 為準。

## 為什麼：提問被後面的回合淹沒 {#why}

yolo 下塔台同時看好幾個 Worker。一個 Worker 碰到斷點、塔台停下來問你「A、B、C 選哪個」，下一秒另一個 Worker 回報完成，塔台收單、派下一張，又是一大段輸出。等你回到塔台分頁，那個問題已經被捲到好幾個畫面之外；塔台後面的回覆看起來一切正常，你不會知道上面還有一題沒答，而那張工單（以及依賴它的工單）就一直停著。

以前的補救都是「把話說得更醒目」：⏸ 標記、粗體、重複一次。問題不在醒不醒目，而在**它是一段會被捲走的文字**。所以契約 v2 換了做法：

1. **要你做的事變成資料**：寫進 `_tower-state.md` 的 frontmatter，有編號、有選項、有建立時間。文字會被捲走，檔案裡的一筆不會。
2. **BAT 把資料放在固定位置**：BAT 右側欄新增「待辦」分頁，列出待你決定、待你執行、到期提醒，以及哪些工單在等你。
3. **不靠 BAT 的那一半也一起做**：塔台每次回覆的最後一行固定重列還沒結的項目。終端、Claude 面板、舊 BAT 都看得到。

**分工照舊：CT 寫，BAT 讀。** 這和 BAT 塔台面板讀取契約（v1）是同一個方向。BAT 只讀、**不改 CT 的任何檔**，連「已回答」也不由 BAT 標記；清單裡的項目消失，就是已經結了。兩邊各只有一個寫入者，不會出現「BAT 標了已回答、塔台卻沒收到」這種兩份狀態對不上的情況。**兩邊都是 v2 才啟用**：任一邊比較舊，就各自照舊運作，不會半套。

## 寫什麼：記住名字就好 {#fields}

| 欄位 | 在哪 | 一句話 |
|---|---|---|
| `bat_contract: 2` | `_tower-state.md` frontmatter | 這份狀態檔照契約 v2 寫；整數、不加引號；6.1.0 起每次寫入都寫 |
| `ct_version` | 同上 | 寫入這份檔的 CT 版號；BAT 只顯示 |
| `awaiting_user` | 同上 | **待你決定**，每筆 `U-n`：哪張工單、什麼來源（哪個斷點或提問）、一句摘要、選項 |
| `user_actions` | 同上 | **待你執行**，每筆 `A-n`：實機驗收（`verify`）、要你跑的指令（`run`）、手動操作（`manual`） |
| `reminders` | 同上 | 專案的定期事項與到期日 |
| `next_ids.user`／`next_ids.action` | 同上 | 下一個 `U-n`／`A-n`；專案內遞增、不重用 |
| `recommended` | `awaiting_user` 的每一筆 | 6.2.0 起。塔台推薦的選項代號；沒有推薦、或是自由回答的題目就不寫（見[推薦項](#recommended)） |
| `inbox_features` | `_tower-state.md` frontmatter | 6.2.0 起。這個塔台多會了哪些事，每次寫入都寫 `["recommended", "dismiss"]`（`user_inbox: off` 也寫）；BAT 看到 `dismiss` 才顯示放棄類的控制項 |
| `waiting_user` | **工單** frontmatter | 這張工單在等你決定哪一題 |

契約 v1 的欄位一個都沒動，`summary_version` 仍是 `1`：它回答的是「我讀得懂這份摘要嗎」，新增欄位不升版。BAT 要知道的是另一件事——「這個塔台和我說同一版的協作規則嗎」——所以另開 `bat_contract`。

6.2.0 加的 `recommended` 與 `inbox_features` 也是新增欄位，所以 `bat_contract` 仍是 `2`。升到 3 的代價太大：舊 BAT（0.8.0-pre.3）讀到 3 會判成版本不符，把整個待辦分頁藏起來，兩個「加上去」的小功能卻讓舊 BAT 的使用者連既有的清單都看不到。所以改用能力旗標：`inbox_features` 只說這個塔台多會了哪些事，讀者忽略不認得的值，沒有這個鍵就當成 6.1.x 的塔台。它只放在狀態檔，不加進開工宣告：判斷「看不看得懂放棄」，看寫這份狀態檔的 CT 版本就夠了。

## 什麼時候寫、什麼時候清 {#lifecycle}

**寫待你決定（`U-n`）**：塔台停下來要你決定時，在顯示暫停訊息的同一次寫入加一筆，有工單時工單同時加 `waiting_user`。來源是 yolo 斷點 A、B-1、B-2、C、E 的暫停（見 [yolo 與斷點 A–E](./yolo)）、Worker 的提問超出塔台能代決的範圍而升級給你（見 [Worker 向塔台提問](./worker-questions)），以及塔台自己停下來等你、而且不是同一輪對話就接著做的事。暫停訊息本身也帶上同一個編號（「待決編號：U-3」「請回覆 U-3：A／B／C」）。

**不寫**：斷點 D（它本來就不暫停，你要去 Worker 分頁處理）、你自己中斷 yolo、需求對齊時一來一往的提問。原則是「會停在那裡等你的才寫」：清單的價值在於裡面每一筆都真的在等你。

**寫待你執行（`A-n`）**：收單時，Worker 回報區列的「待實機／待使用者執行」項目各寫一筆，收單確認裡列出新的 `A-n`。以前這類項目寫在 `todo`，跟塔台自己的待辦混在一起；現在改寫這裡，`todo` 不再重複列。

**清掉**：你回答後，塔台在同一次寫入移除那一筆、清掉工單的 `waiting_user`，並在決策日誌記一筆。`A-n` 回「完成」或「失敗」都移除；失敗的後續由塔台開 BUG 或重開工單承接，不讓同一筆一直掛著。6.2.0 起多兩種結法：`U-n：放棄`、`A-n：略過`（見[放棄與略過](#dismiss)）。

**`A-n：失敗` 但塔台複查結果不同（6.1.1 起寫進規格）。** 塔台收到失敗回報後會自己複查；複查結果與回報不符時（例：你回報失敗，塔台看到的實況是成功），不開 BUG、也不重開工單，改發一筆 `U-n` 請你裁示，選項至少有「不處理」「開 BUG 追查」「再發一筆 `A-n` 重驗」，決策日誌寫明比對結果。

**決策日誌還不存在時（6.1.1 起寫進規格）。** 塔台平常不主動建立 `_decision-log.md`；但你回答 `U-n`／`A-n`、要記一筆而它還不存在時，塔台直接以初始模板建立再記，不另外問你。

這兩件事是 6.1.0 實機驗收時塔台已經這樣做、判定合理的做法，6.1.1 補進規格，欄位與回答格式都沒變。

**依賴的工單在等你 → 先不派。** 派工前塔台看 `depends_on`：依賴的工單有 `waiting_user`，這張就先不派，印一行說明在等哪一題；其他工單照常派。

**不自動遷移。** 升到 6.1.0 時，舊 `todo` 裡「等你決定」「等你實機驗收」的項目不會被批次改寫，塔台下次處理到那一項時再搬。

## 回答：一行就好 {#answer}

| 你要做的 | 回覆 |
|---|---|
| 選一個選項 | `U-3：B` |
| 不在選項裡的答案 | `U-3：<你自己的話>` |
| 做完了 | `A-2：完成` |
| 做了但失敗 | `A-2：失敗 <哪裡不對>` |
| 都不選、先停下（6.2.0 起） | `U-3：放棄`，或附原因、新方向：`U-3：放棄 改做 X` |
| 這一項不做了（6.2.0 起） | `A-2：略過`，或附原因：`A-2：略過 換機器了` |
| 一次好幾題（6.2.0 起，只用在放棄與略過） | `U-1、U-4：放棄`、`A-2、A-3：略過` |

- 全形 `：` 與半形 `:` 都可以；一則訊息可以有好幾行，逐行處理。
- 代號不分大小寫，而且要**只命中一個選項**才算選了它，否則整段當自由回答：寧可當成你寫的一句話，也不要猜錯成某個選項。
- 只有一題在等、你直接回 `B`：塔台照那一題處理，確認行會寫出 `U-n`。
- 塔台回一行確認，例如 `U-3 已收到：B → 恢復 T0001`、`A-2 已收到：完成`。
- 你可以在塔台分頁自己打，也可以用 BAT 待辦分頁的回答框：它送進塔台分頁的就是同一行字，CT 不區分。

### 回覆結尾重列：任何終端都有 {#reply-end}

有東西在等你時，塔台**每次回覆的最後一行**固定是這一行（沒有項目的那半段不印，兩邊都沒有就整行不印）：

```
⏸ 待你決定：U-3（T0001）、U-5（—）；🙋 待你執行：A-2（安裝新版後做一次完整重裝驗收）——回覆「U-n：選項」或「A-n：完成」
```

這一行只是提醒，資料在 frontmatter；它不取代問問題的那則暫停訊息。放在最後一行，是因為那是你回到分頁時第一眼看到、也最不會被後面的輸出蓋掉的位置。它不依賴 BAT，所以舊 BAT、非 BAT 終端、Claude 面板開的塔台都一樣有。6.2.0 起可以改成只在清單有變化時印，見[提醒頻率](#pending-reminder)。

## 推薦項：排第一、寫「（推薦）」、再寫一個欄位（6.2.0 起） {#recommended}

6.1.0 把提問搬進檔案以後，`awaiting_user` 只剩 `options` 一串文字，分頁看不出塔台建議哪一項。6.2.0 起塔台有推薦時，三個動作一起做：

| 動作 | 給誰看 |
|---|---|
| 推薦項排第一個 | 所有人：終端、舊 BAT、新 BAT 都看得到順序 |
| 說明結尾加「（推薦）」 | 看不到欄位的讀者：終端回覆、舊 BAT、BAT 以外的工具 |
| 同一筆寫 `recommended`（推薦項的代號） | BAT 0.8.0-pre.4 起：顯示推薦標記、預設選取那一項 |

有了欄位還保留「（推薦）」，是因為欄位只有新 BAT 讀得懂；拿掉文字，終端與舊 BAT 的使用者就又看不出推薦了。畫面上同時有標記和「（推薦）」，CT 接受這點重複。

- **沒有推薦就兩者都不寫**：兩個選項各有利弊、要你憑偏好決定時，塔台不硬挑一個。自由回答的題目（沒有選項）也不寫 `recommended`。
- **暫停訊息照同一個排法**：斷點與提問的選項清單也是推薦項排第一、標「（推薦）」。
- **寫完自己對過**：`recommended` 要對得到同一筆的某個選項代號（不分大小寫），對不到就不寫；`check-frontmatter.py` 會把對不到、型別不對、自由回答卻寫了推薦這三種情況報出來。BAT 遇到對不到的值當作沒有推薦，不報錯。

## 放棄與略過（6.2.0 起） {#dismiss}

有時整批不做了、問題已經不合時宜，或要換個方向：所有選項都不適用。以前只能打一段自由文字，塔台還得猜你是不是要放棄。6.2.0 起有兩個詞：

| 你回 | 意思 | 塔台會怎麼做 |
|---|---|---|
| `U-3：放棄` | 這個決定我不選任何選項 | 移除這一題、不套用任何選項；相關工單**維持暫停** |
| `A-2：略過` | 這件事我不做了 | 移除這一項；**不開 BUG、不重開工單**；決策日誌記「未驗（使用者略過）」 |
| `A-2：失敗 <說明>`（原有） | 我做了，但沒過 | 照 6.1.x：依內容開 BUG 或重開工單 |

「略過」和「失敗」刻意分開：沒做的驗收不能記成驗過，也不該被當成發現問題。

- **沒附文字**（`U-3：放棄`）：塔台不會再開一題問你新方向（剛放棄的題目換個編號又冒出來，清單永遠清不空）。它清掉工單的 `waiting_user`，在 `todo` 留一則「暫停中，等新方向」，在當次回覆告訴你，等你下次指示。
- **附了文字**（`U-3：放棄 改成先做 X`）：塔台照你的話重新對齊。要改範圍、驗收條件，或屬於不可逆、對外發布的動作，照舊先問你。
- **工單狀態都不改**：`BLOCKED` 還是 `BLOCKED`，yolo 斷點的暫停也不會因為放棄就自己繼續。放棄是「不選這些選項」，不是「照預設往下走」。
- **什麼時候算數**：只有冒號後**第一個詞**是「放棄」「略過」時才算，後面的文字是原因或新方向。你想用自由文字回答、剛好第一個詞是「放棄」時會被當成放棄；確認行會寫明「U-3 已放棄」，看到不對就重新回答。手打時混用也沒關係：`U-n：略過` 當成放棄、`A-n：放棄` 當成略過。

### 一次好幾題 {#batch}

`U-1、U-3、U-4：放棄 這批不做了`：冒號前列明確的編號，分隔用 `、`、`,` 或全形 `，`，後面附的文字套用到每一題。

- **只用在放棄與略過**：`U-1、U-3：A`（好幾題選同一個選項）不支援，塔台不猜，回一行請你逐題回答。
- **不接受萬用字元與範圍**：`U-*`、`U-1～U-5` 都不收。BAT 的「全部放棄」會在你按下的當下展開成畫面上看得到的編號再送出，免得把你還沒看到、剛寫進來的新題目一起放棄。
- **已經不在清單的編號就略過**，其他照做；確認行會說清楚，例如「U-1、U-3 已放棄；U-4 已不在清單，略過」。
- 同一行可以混 `U` 和 `A`（`U` 讀成放棄、`A` 讀成略過）。批次放棄在決策日誌只記**一筆**，列出全部編號。

## 暫停改開原生選單（6.2.0 起） {#menu}

塔台停下來等你決定時（yolo 斷點、非 yolo 的合併前確認、Worker 的提問轉給你、塔台自己的提問），6.1.x 是印一段文字範本，等你打 `U-n：B`。6.2.0 起改成先照舊寫好待決（`U-n`），**再**開 Claude Code 的原生選單，點一下就好。這沿用既有的 `interactive-prompts`（預設 `on`），沒有新增設定；`*config interactive-prompts off` 就回到 6.1.x 的文字暫停。它只決定問法，要不要把清單寫進檔案仍是 `user_inbox`。

- **題目本身寫完整**：`U-n`、工單、一句話說要決定什麼。選單前面的文字你可能看不到，所以不能只靠前面那段說明。
- **選項**：推薦項排第一、標「（推薦）」；每個選項的開頭是和待辦清單相同的代號（`A`、`B`…），在 BAT 看到的和在選單看到的對得起來。
- **放棄項**：題目有 1～3 個選項時，最後**一定**多一項「放棄（停下等新方向）」，選了就等於 `U-n：放棄`；剛好 4 個選項時選單已滿，題目結尾提示在「其他」打「放棄」。「其他」可以打自由文字，以「放棄」開頭也算放棄。
- **改用文字的題目**：原生選單最多 4 個選項，超過 4 個的題目改用文字範本；沒有選項的自由回答題也直接用文字問（選單每題要 2～4 個選項，硬湊一個假選項會讓你以為塔台有預設答案）。
- **怎麼回答都算數**：選單、在終端打 `U-n：…`、BAT 待辦分頁送出。選單開著時你在待辦分頁按了送出，BAT 會先留著，選單關掉才送到塔台；如果你已經在選單答過同一題，後到的那行照「編號已結」處理，不會套用兩次。選單開著時 Worker 的完成通知也一樣先留著，不會替你選。
- **按 Esc**：在 Claude Code 裡等於中斷，那一回合直接結束，塔台連說一句話的機會都沒有。所以該筆照留（不算回答、不算放棄），塔台在**你下一次說話後的那一則回覆**開頭提醒哪幾筆的選單被關掉、仍待決，並重列。之後的暫停仍開選單；想改用文字請設 `interactive-prompts off`。

**什麼時候自動改用文字**（即使 `on`）：

| 情況 | 為什麼 |
|---|---|
| Codex 塔台 | 沒有原生選單 |
| 在 BAT 內，但開工時 `BAT 契約` 不是 `v2`（舊 BAT 或宣告失敗） | 選單開著時，Worker 的通知會打字再按 Enter；只有契約 v2 的 BAT 保證先把通知留著，等選單關掉再送。沒有這個保證，那個 Enter 可能替你選了選項 |
| 不在 BAT 裡的終端 | **不改**，照用選單：沒有 Worker 會自動寫進塔台分頁 |

## 回覆結尾提醒的頻率：`pending_reminder`（6.2.0 起） {#pending-reminder}

6.1.0 起，只要有待決或待執行，塔台每則回覆的最後一行都是 `⏸ 待你決定：…；🙋 待你執行：…`。用的人回饋（GitHub issue #1）：連續好幾則都在處理別的事，那一行卻每則都在，太吵。6.2.0 加了設定 `pending_reminder`：

| 值 | 什麼時候印那一行 |
|---|---|
| `every`（預設） | 有待決時每則回覆都印，和 6.1.x 一樣 |
| `on-change` | 只在這幾個時候印整行：本 session 第一則回覆；清單**多了**新的 `U-n`／`A-n`；你問「目前有什麼待決？」或下 `*sync`（完整列出）；暫停選單被 Esc 關掉後的下一則回覆 |

- **「移除」不算變化**：你回答或放棄一題時，塔台本來就會回一行確認（`U-3 已收到：B`、`U-3 已放棄`），再重列一次是重複。
- **Esc 那一則不受 `on-change` 限制**：選單被你關掉了，那是塔台唯一能告訴你「它還在等」的地方。
- **不受影響的**：狀態檔裡的三個清單照寫、BAT 待辦分頁照常顯示、暫停訊息與選單照開、`user_inbox` 照舊。`pending_reminder` 只管終端那一行。
- **已知限制**：「已經提醒過」是塔台看對話內容判斷的。對話被壓縮之後它不記得前面印過，可能多提醒一次；多一次無害，所以不另外記狀態。

設定方式：`*config pending_reminder on-change --save project`（見[指令參考大全 › `*config`](/reference/commands#config)）。

## 開工宣告：先寫狀態檔，再告訴 BAT {#declare}

塔台本來每次啟動就會用 `--set-role tower` 向 BAT 宣告分頁角色（見[派工 › BAT 派工](./dispatch#bat)）。6.1.0 在同一個呼叫多帶 `--bat-contract 2`，順序是：

1. `_tower-state.md` 還沒有 `bat_contract: 2`（含第一次開工）→ **先寫入**；
2. 帶 `--bat-contract 2` 呼叫 `--set-role tower`；
3. 讀輸出的 `bat-contract:` 與 `hooks:` 兩行。

先寫檔再宣告，是因為 BAT 看到分頁宣告 v2 時會去讀狀態檔，順序反過來就會先讀到一份還不是 v2 的檔。每次 `--set-role` 都要帶這個參數（`*config auto-session` 改模式時的再宣告也一樣），因為 BAT 每次都覆寫這個分頁的宣告，不帶就等於清掉。

狀態面板多一欄 `BAT 契約`：

| `BAT 契約` | 什麼情況 |
|---|---|
| `v2` | BAT 回 `bat-contract: 2` |
| `不支援（BAT 太舊）` | BAT 不支援 v2，或根本不認得這個參數（下一節） |
| `未知（宣告失敗）` | `--set-role` 本身失敗（連線、權杖等），照舊不重試、不擋開工 |
| `略過（非 BAT）` | 不在 BAT 裡，或是 Claude 面板開的塔台 |

CT 只看這一次呼叫的輸出；BAT MCP 雖然也查得到這個分頁的契約版本與 hooks 狀態，CT 不拿那些欄位判斷。

## 舊 BAT 與非 BAT：降級，不會半套 {#fallback}

**舊 BAT：只重送一次。** 太舊的 helper 不認得 `--bat-contract`，會回 exit `1` 加 `Unknown option '--bat-contract'`，而且沒有設定角色。塔台不帶這個參數重送一次，分頁標題與模式照舊可用，本 session 之後都不再帶；開工面板印一行降級提示：

```
⚠️ 這版 BAT 不支援 BAT ↔ CT 契約 v2（需要 BAT ≥ 0.8.0-pre.3）：待辦分頁、通知保護、回合訊息卡不可用；待決事項仍會列在每次回覆的結尾。
```

這和 `--wait-started` 的處理是同一個模式：先送、失敗才降級、只降一次（見[降級鏈](./dispatch#fallback)）。再多試幾次也不會讓舊 BAT 變新，只會把開工拖長。

| 組合 | 會看到什麼 |
|---|---|
| CT 6.1.0＋BAT `>= 0.8.0-pre.3` | 待辦分頁、通知保護、回合訊息卡；面板 `BAT 契約：v2` |
| CT 6.1.0＋舊 BAT | 沒有待辦分頁；開工面板一行降級提示；標題、模式、派工、回收照舊；回覆結尾照樣重列 |
| CT 6.1.0＋非 BAT 終端或 Claude 面板 | 不宣告；v2 欄位照寫、回覆結尾照印 |
| CT 6.0.x＋新 BAT | 塔台不宣告 v2，BAT 的待辦分頁說明需要哪一版、保持關閉；其他照舊 |

**通知保護**與**回合訊息卡**是 BAT 這一端的功能，對宣告了 v2 的塔台分頁才啟用：你在塔台分頁打字到一半時，Worker 的完成通知不會帶著半句送出；權限對話框開著時通知保留、不替你回答。回合訊息卡是每回合一張卡片，回覆結尾的重列行會加亮。各版本的門檻見[相容版本對照](/versions/compatibility)。

### CT 6.2.0 與 BAT 0.8.0-pre.4 {#versions}

推薦標記與放棄控制項要 BAT 0.8.0-pre.4 以上（與 CT 6.2.0 同日發佈）；契約 v2 的最低版本仍是 0.8.0-pre.3，開工時的降級提示不變。

| CT | BAT | 看得到什麼 |
|---|---|---|
| 6.2.0 | 0.8.0-pre.4 以上 | 推薦標記與預設選取、放棄／略過、批次勾選、「全部放棄」 |
| 6.2.0 | 0.8.0-pre.3 | 待辦分頁照常（契約 2 相符）；沒有推薦標記，但推薦項排第一、說明有「（推薦）」；沒有放棄按鈕，在塔台的輸入框打 `U-n：放棄` 一樣有效 |
| 6.1.x | 0.8.0-pre.4 以上 | 狀態檔沒有 `inbox_features`，所以沒有推薦標記、沒有放棄控制項；其他照舊 |
| 6.1.x | 0.8.0-pre.3 | 和 6.1.x 一樣 |

第二列成立的前提是舊 BAT 會略過不認得的鍵；6.2.0 發佈前的實機驗收也看過：搭 0.8.0-pre.3 時待辦分頁照常。0.8.0-pre.3 只有沒有選項的待決有自由回答欄，有選項的那一題要放棄，就在塔台的輸入框打。

## 兩種 hooks，不是同一件事 {#hooks}

`hooks:` 那一行講的是 **BAT 的 hooks**：BAT 用自己的 claude hooks 知道塔台的 Claude 在做什麼（回合結束、停在對話框、回合訊息卡要的最後一則訊息）。BAT 開的 Claude 分頁會自動加上；但你在 shell 分頁手打 `claude`、在 agent 自訂參數放了 `--settings`、或在 BAT 設定裡關了 BAT MCP 時就沒有。

- BAT 回 `hooks: none (<原因代號>)` 時，塔台在開工面板印一行「這個塔台沒有 BAT hooks：回合訊息卡與對話框保護不可用。」，後面接原因與怎麼修（例如拿掉 `--settings`、改用 BAT「以塔台開啟 Claude」，或安裝 BAT 的 `bat-hooks` plugin）。`hooks: ok …` 與 Codex 的 `hooks: n/a (codex)` 不印，沒問題的事不佔面板。
- 裝了 `bat-hooks` plugin 但它比這版 BAT 舊時，面板提示執行 `claude plugin update bat-hooks@better-agent-terminal`。
- **什麼時候需要 `bat-hooks` plugin**：只有在 BAT 沒辦法替你自動加上 hooks 的時候（上面三種情況）。在塔台問 `/ct-help`〈與 BAT 協作〉可以看到說明。
- **CT 自己的 hooks 是另一件事**，不屬契約 v2。
- **CT 不替你安裝 plugin、不改你的 claude 設定**：面板只告訴你怎麼做，裝不裝由你決定。

## 不想寫進檔案：`user_inbox: off` {#user-inbox}

`*config user_inbox off`（加 `--save project` 保存）之後，塔台就不寫 `awaiting_user`、`user_actions`，退回 6.0.x 的做法：待決只在終端、待執行照舊放 `todo`。`bat_contract`、`ct_version`、`reminders`、工單的 `waiting_user` 照寫，**回覆結尾照印**。典型情境是 `_ct-workorders/` 會公開的專案。它關的是「寫清單」，不是契約 v2：開工宣告照常、`bat_contract` 照寫。6.2.0 起 `inbox_features` 也照寫（能力和要不要寫清單是兩件事），在終端回 `U-n：放棄`、`A-n：略過` 一樣有效。

其他幾個寫法上的約定：

- **隱私**：摘要、標題、選項、指令不寫祕密、權杖、客戶資料或真實個人資料；需要細節就寫「見某工單回報區」。這些欄位會顯示在 BAT 面板上，也跟著 repo 走。
- **時區**：契約 v2 新欄位的時間寫成 `+08:00` 這種帶冒號的時區，既有欄位（`updated_at` 等）維持 `+0800`；兩者都取自系統時間，不手打。
- **筆數上限**：待決、待執行各 20 筆，提醒 10 筆。超過時開工面板多一行提示，不擋流程。
- **寫完自檢多了 v2 的檢查**：6.0.1 起的 `check-frontmatter.py` 對狀態檔另檢查 v2 欄位的型別、編號格式、選項代號、字數與日期，對工單檢查 `waiting_user`（見[字串寫法與寫入後自檢](/deep/principles/files-as-truth#yaml-strings)）。6.2.0 起另檢查 `recommended`（字串、對得到同一筆的選項代號、自由回答時不應有）與 `inbox_features`（字串清單；不認得的值不報錯）。筆數超過上限是警告（`WARN`），不影響 exit code；其他問題仍是失敗、不得 commit。

## 驗了什麼、還沒驗什麼 {#verified}

6.1.0 發佈前，在 BAT 0.8.0-pre.3 的測試版上用隔離的 BAT 執行環境與隔離的 claude 設定目錄實機跑過（舊 BAT 降級用的是 BAT 0.8.0-pre.1）：

- 開工宣告與解析（先寫欄位再宣告、兩行都解析到、面板 `BAT 契約：v2`、改模式再宣告也帶參數）
- 從 6.0.2 換版（第一次開工補上欄位再宣告，既有 `todo` 原樣保留）
- 舊 BAT 降級（只重送一次、降級提示原文、之後不再帶參數）
- 待決與待執行的寫入、從 BAT 待辦分頁送出的回答、一行確認、移除並記決策日誌、編號只增不減
- 回覆結尾重列（每則回覆、兩邊都空不印、斷點 A 暫停時、舊 BAT 下也重列）
- 通知保護、回合訊息卡、`bat-hooks` plugin 並存（`hooks: ok`、卡片不重複）、CT 的長指令防護照常

還沒實機驗過的路徑：`hooks: none` 與 `plugin-outdated` 的提示行；「BAT 認得參數但不支援 v2」的兩種輸出；非 BAT 終端與 Codex 塔台；斷點 B-1、B-2、C、E 與 Worker 提問升級寫待決；工單的 `waiting_user` 與「依賴的工單在等你時先不派」；收單時自動寫 `A-n`；`user_inbox: off`、`reminders` 與筆數警告。完整清單見[更版紀錄 v6.1.0](/versions/releases#v6-1-0)。6.1.1 補進規格的兩句（見[什麼時候寫、什麼時候清](#lifecycle)）是照 6.1.0 驗收時的實況寫的，換上 6.1.1 後還沒在新的塔台 session 再觀察（見[更版紀錄 v6.1.1](/versions/releases#v6-1-1)）。

6.2.0 發佈前，在 BAT 0.8.0-pre.4 的測試版上，同樣用隔離的 BAT 執行環境與隔離的 claude 設定目錄實機跑過兩輪：先以 6.2.0-pre.1 跑完整清單，再以 6.2.0-pre.2 補跑修正過的部分。第一輪唯一不合格的「3 個選項的選單沒有放棄」與沒觸發到的「Esc 後的提醒」，都在 pre.2 修正條文後補跑通過：

- 推薦項（排第一、「（推薦）」、`recommended`；自由回答不寫；BAT 標記並預設選取）與 `inbox_features`（換版後第一次寫就帶、之後每次都帶、開工宣告不帶）
- 單筆與批次的放棄與略過、已結編號、BAT「全部放棄」送出明確編號、不支援的寫法（`U-*`、範圍、批次選同一個選項）塔台不猜
- 新舊版本搭配：CT 6.2.0 搭 BAT 0.8.0-pre.3、CT 6.1.1 搭新 BAT
- 暫停的原生選單：先寫待決再開、放棄項、在「其他」輸入「放棄 …」、自由回答改用文字；Esc 之後下一則提醒並重列、之後仍開選單；選單與待辦分頁的競態
- `interactive-prompts: off` 與 BAT 契約不是 v2 時改用文字；`pending_reminder: on-change`

6.2.0 還沒實機驗過的路徑：Codex 塔台；塔台提問以外的暫停改開選單（斷點 A／B-1／B-2／C／E、非 yolo 的合併前確認、Worker 提問升級，實機只走過「塔台提問」）；選項剛好 4 個與超過 4 個的題目；不在 BAT 裡的終端開選單；連續 FAILED／BLOCKED 計數器的新標籤；`on-change` 在對話被壓縮之後的行為。完整清單見[更版紀錄 v6.2.0](/versions/releases#v6-2-0)。
