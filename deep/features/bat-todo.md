# 待辦分頁（BAT ↔ CT 契約 v2）

<p class="ct-lead">一句話：塔台要你做的事，從「終端裡的一段話」變成「檔案裡的一筆資料」。CT 把要你決定的事（<code>U-n</code>）和要你自己執行的事（<code>A-n</code>）寫進 <code>_tower-state.md</code> 的 frontmatter，BAT 的「待辦」分頁唯讀顯示；不用 BAT 的人也一樣，有東西在等你時，塔台每次回覆的最後一行都會重列一次。沒有東西在等你時，什麼都不多。</p>

v6.1.0 起屬正式版（6.1.0-pre.1 預覽時加入），已在 BAT 0.8.0-pre.3 的測試版上實機驗證。6.2.0 起加上[推薦項](#recommended)、[放棄與略過](#dismiss)、[暫停改開原生選單](#menu)與[提醒頻率 `pending_reminder`](#pending-reminder)（6.2.0-pre.1 預覽時加入、pre.2 依實機驗收修正），已在 BAT 0.8.0-pre.4 的測試版上實機驗證。6.3.0 起[放棄附的文字只當原因](#dismiss-reason)，並加上[多選](#multi)與[確認行](#confirm)（6.3.0-pre.1 預覽時加入，pre.2、pre.3 依實機驗收修正確認行），已在 BAT 0.8.0-pre.8 上實機驗證。6.4.0 起[選單開著時也能在待辦分頁作答](#menu-handoff)，[被關掉的選單不重開](#menu-closed)（6.4.0-pre.1 預覽時加入，pre.2 依實機驗收補上寫入位置與文字問的題），已在 BAT 0.8.1-pre.4 上實機驗證。本頁是摘要；確切的欄位、上限、回答寫法與訊息字樣以 CT `memory-protocol.md` § 契約 v2 欄位（含〈暫停的提問方式〉）與 `auto-session.md` § 塔台分頁角色宣告為準，提醒頻率以 `control-tower/SKILL.md` § Output Style 為準。

## 為什麼：提問被後面的回合淹沒 {#why}

yolo 下塔台同時看好幾個 Worker。一個 Worker 碰到斷點、塔台停下來問你「A、B、C 選哪個」，下一秒另一個 Worker 回報完成，塔台收單、派下一張，又是一大段輸出。等你回到塔台分頁，那個問題已經被捲到好幾個畫面之外；塔台後面的回覆看起來一切正常，你不會知道上面還有一題沒答，而那張工單（以及依賴它的工單）就一直停著。

以前的補救都是「把話說得更醒目」：⏸ 標記、粗體、重複一次。問題不在醒不醒目，而在**它是一段會被捲走的文字**。所以契約 v2 換了做法：

1. **要你做的事變成資料**：寫進 `_tower-state.md` 的 frontmatter，有編號、有選項、有建立時間。文字會被捲走，檔案裡的一筆不會。
2. **BAT 把資料放在固定位置**：BAT 右側欄新增「待辦」分頁，列出待你決定、待你執行、到期提醒，以及哪些工單在等你。
3. **不靠 BAT 的那一半也一起做**：塔台每次回覆的最後一行固定重列還沒結的項目。終端、Claude 面板、舊 BAT 都看得到。

**分工照舊：CT 寫，BAT 讀。** 這和 BAT 塔台面板讀取契約（v1）是同一個方向。BAT 只讀、**不改 CT 的任何檔**，連「已回答」也不由 BAT 標記；清單裡的項目消失，就是已經結了。兩邊各只有一個寫入者，不會出現「BAT 標了已回答、塔台卻沒收到」這種兩份狀態對不上的情況。**兩邊都是 v2 才啟用**：任一邊比較舊，就各自照舊運作，不會半套。

## 寫什麼：記住名字就好 {#fields}

| 欄位 | 在哪 | 一句話 |
|---|---|---|
| `bat_contract: 2` | `_tower-state.md` frontmatter | 這份狀態檔照契約 v2 寫；整數、不加引號；6.1.0 起每次寫入都寫 |
| `ct_version` | 同上 | 寫入這份檔的 CT 版號；BAT 只顯示 |
| `awaiting_user` | 同上 | **待你決定**，每筆 `U-n`：哪張工單、什麼來源（哪個斷點或提問）、一句摘要、選項 |
| `user_actions` | 同上 | **待你執行**，每筆 `A-n`：實機驗收（`verify`）、要你跑的指令（`run`）、手動操作（`manual`） |
| `reminders` | 同上 | 專案的定期事項與到期日 |
| `next_ids.user`／`next_ids.action` | 同上 | 下一個 `U-n`／`A-n`；專案內遞增、不重用 |
| `recommended` | `awaiting_user` 的每一筆 | 6.2.0 起。塔台推薦的選項代號（6.3.0 起多選題可以寫好幾個，以 `、` 連接）；沒有推薦、或是自由回答的題目就不寫（見[推薦項](#recommended)） |
| `multi` | `awaiting_user` 的每一筆 | 6.3.0 起。`true` 表示這一題可以複選；只在塔台或 Worker 的提問、選項可以同時成立、至少 2 個選項時寫（見[多選](#multi)） |
| `inbox_features` | `_tower-state.md` frontmatter | 6.2.0 起。這個塔台多會了哪些事，每次寫入都寫 `["recommended", "dismiss"]`，6.3.0 起是 `["recommended", "dismiss", "multi"]`，6.4.0 起是 `["recommended", "dismiss", "multi", "menu"]`（`user_inbox: off` 也寫）；BAT 看到 `dismiss` 才顯示放棄類的控制項，看到 `multi` 才把多選題畫成複選，看到 `menu` 才照 `menu_open` 關選單 |
| `menu_open` | `_tower-state.md` frontmatter | 6.4.0 起。塔台給 BAT 的內部欄位：開著的原生選單裡有哪些 `U-n`；BAT 據此先關選單、再送出待辦分頁的回答。你不必處理（見[選單開著時在待辦分頁作答](#menu-handoff)） |
| `waiting_user` | **工單** frontmatter | 這張工單在等你決定哪一題 |

契約 v1 的欄位一個都沒動，`summary_version` 仍是 `1`：它回答的是「我讀得懂這份摘要嗎」，新增欄位不升版。BAT 要知道的是另一件事——「這個塔台和我說同一版的協作規則嗎」——所以另開 `bat_contract`。

6.2.0 加的 `recommended` 與 `inbox_features` 也是新增欄位，所以 `bat_contract` 仍是 `2`。升到 3 的代價太大：舊 BAT（0.8.0-pre.3）讀到 3 會判成版本不符，把整個待辦分頁藏起來，兩個「加上去」的小功能卻讓舊 BAT 的使用者連既有的清單都看不到。所以改用能力旗標：`inbox_features` 只說這個塔台多會了哪些事，讀者忽略不認得的值，沒有這個鍵就當成 6.1.x 的塔台。它只放在狀態檔，不加進開工宣告：判斷「看不看得懂放棄」，看寫這份狀態檔的 CT 版本就夠了。6.3.0 的 `multi`、6.4.0 的 `menu` 都照同一個做法加進 `inbox_features`，`bat_contract` 仍是 `2`。

## 什麼時候寫、什麼時候清 {#lifecycle}

**寫待你決定（`U-n`）**：塔台停下來要你決定時，在顯示暫停訊息的同一次寫入加一筆，有工單時工單同時加 `waiting_user`。來源是 yolo 斷點 A、B-1、B-2、C、E 的暫停（見 [yolo 與斷點 A–E](./yolo)）、Worker 的提問超出塔台能代決的範圍而升級給你（見 [Worker 向塔台提問](./worker-questions)），以及塔台自己停下來等你、而且不是同一輪對話就接著做的事。暫停訊息本身也帶上同一個編號（「待決編號：U-3」「請回覆 U-3：A／B／C」）。

**不寫**：斷點 D（它本來就不暫停，你要去 Worker 分頁處理）、你自己中斷 yolo、需求對齊時一來一往的提問。原則是「會停在那裡等你的才寫」：清單的價值在於裡面每一筆都真的在等你。

**寫待你執行（`A-n`）**：收單時，Worker 回報區列的「待實機／待使用者執行」項目各寫一筆，收單確認裡列出新的 `A-n`。以前這類項目寫在 `todo`，跟塔台自己的待辦混在一起；現在改寫這裡，`todo` 不再重複列。

**清掉**：你回答後，塔台在同一次寫入移除那一筆、清掉工單的 `waiting_user`，並在決策日誌記一筆。`A-n` 回「完成」或「失敗」都移除；失敗的後續由塔台開 BUG 或重開工單承接，不讓同一筆一直掛著。6.2.0 起多兩種結法：`U-n：放棄`、`A-n：略過`（見[放棄與略過](#dismiss)）。

**`A-n：失敗` 但塔台複查結果不同（6.1.1 起寫進規格）。** 塔台收到失敗回報後會自己複查；複查結果與回報不符時（例：你回報失敗，塔台看到的實況是成功），不開 BUG、也不重開工單，改發一筆 `U-n` 請你裁示，選項至少有「不處理」「開 BUG 追查」「再發一筆 `A-n` 重驗」，決策日誌寫明比對結果。

**決策日誌還不存在時（6.1.1 起寫進規格）。** 塔台平常不主動建立 `_decision-log.md`；但你回答 `U-n`／`A-n`、要記一筆而它還不存在時，塔台直接以初始模板建立再記，不另外問你。

這兩件事是 6.1.0 實機驗收時塔台已經這樣做、判定合理的做法，6.1.1 補進規格，欄位與回答格式都沒變。

**依賴的工單在等你 → 先不派。** 派工前塔台看 `depends_on`：依賴的工單有 `waiting_user`，這張就先不派，印一行說明在等哪一題；其他工單照常派。

**不自動遷移。** 升到 6.1.0 時，舊 `todo` 裡「等你決定」「等你實機驗收」的項目不會被批次改寫，塔台下次處理到那一項時再搬。

## 回答：一行就好 {#answer}

| 你要做的 | 回覆 |
|---|---|
| 選一個選項 | `U-3：B` |
| 不在選項裡的答案、新方向 | `U-3：<你自己的話>`，例 `U-3：改做 X` |
| 做完了 | `A-2：完成` |
| 做了但失敗 | `A-2：失敗 <哪裡不對>` |
| 都不選、先停下（6.2.0 起） | `U-3：放棄`，或附原因：`U-3：放棄 規格還沒定`（6.3.0 起文字只當原因，見[為什麼把放棄和新方向分開](#dismiss-reason)） |
| 多選題選好幾個（6.3.0 起） | `U-4：A、C`（見[多選](#multi)） |
| 這一項不做了（6.2.0 起） | `A-2：略過`，或附原因：`A-2：略過 換機器了` |
| 一次好幾題（6.2.0 起，只用在放棄與略過） | `U-1、U-4：放棄`、`A-2、A-3：略過` |

- 全形 `：` 與半形 `:` 都可以；一則訊息可以有好幾行，逐行處理。
- 代號不分大小寫，而且要**只命中一個選項**才算選了它，否則整段當自由回答：寧可當成你寫的一句話，也不要猜錯成某個選項。
- 只有一題在等、你直接回 `B`：塔台照那一題處理，確認行會寫出 `U-n`。
- 塔台回一行確認，例如 `U-3 已收到：B → 恢復 T0001`、`A-2 已收到：完成`。6.3.0 起每一筆回答各一行；同一則回覆處理了回答又要開選單時，確認行寫進選單的題目（見[確認行](#confirm)）。
- 你可以在塔台分頁自己打，也可以用 BAT 待辦分頁的回答框：它送進塔台分頁的就是同一行字，CT 不區分。

### 回覆結尾重列：任何終端都有 {#reply-end}

有東西在等你時，塔台**每次回覆的最後一行**固定是這一行（沒有項目的那半段不印，兩邊都沒有就整行不印）：

```
⏸ 待你決定：U-3（T0001）、U-5（—）；🙋 待你執行：A-2（安裝新版後做一次完整重裝驗收）——回覆「U-n：選項」或「A-n：完成」
```

這一行只是提醒，資料在 frontmatter；它不取代問問題的那則暫停訊息。放在最後一行，是因為那是你回到分頁時第一眼看到、也最不會被後面的輸出蓋掉的位置。它不依賴 BAT，所以舊 BAT、非 BAT 終端、Claude 面板開的塔台都一樣有。6.2.0 起可以改成只在清單有變化時印，見[提醒頻率](#pending-reminder)。

## 推薦項：排第一、寫「（推薦）」、再寫一個欄位（6.2.0 起） {#recommended}

6.1.0 把提問搬進檔案以後，`awaiting_user` 只剩 `options` 一串文字，分頁看不出塔台建議哪一項。6.2.0 起塔台有推薦時，三個動作一起做：

| 動作 | 給誰看 |
|---|---|
| 推薦項排第一個 | 所有人：終端、舊 BAT、新 BAT 都看得到順序 |
| 說明結尾加「（推薦）」 | 看不到欄位的讀者：終端回覆、舊 BAT、BAT 以外的工具 |
| 同一筆寫 `recommended`（推薦項的代號） | BAT 0.8.0-pre.4 起：顯示推薦標記、預設選取那一項 |

有了欄位還保留「（推薦）」，是因為欄位只有新 BAT 讀得懂；拿掉文字，終端與舊 BAT 的使用者就又看不出推薦了。畫面上同時有標記和「（推薦）」，CT 接受這點重複。

- **沒有推薦就兩者都不寫**：兩個選項各有利弊、要你憑偏好決定時，塔台不硬挑一個。自由回答的題目（沒有選項）也不寫 `recommended`。
- **暫停訊息照同一個排法**：斷點與提問的選項清單也是推薦項排第一、標「（推薦）」。
- **寫完自己對過**：`recommended` 要對得到同一筆的某個選項代號（不分大小寫），對不到就不寫；`check-frontmatter.py` 會把對不到、型別不對、自由回答卻寫了推薦這三種情況報出來。BAT 遇到對不到的值當作沒有推薦，不報錯。

## 放棄與略過（6.2.0 起） {#dismiss}

有時整批不做了、問題已經不合時宜，或要換個方向：所有選項都不適用。以前只能打一段自由文字，塔台還得猜你是不是要放棄。6.2.0 起有兩個詞：

| 你回 | 意思 | 塔台會怎麼做 |
|---|---|---|
| `U-3：放棄` | 這個決定我不選任何選項 | 移除這一題、不套用任何選項；相關工單**維持暫停** |
| `A-2：略過` | 這件事我不做了 | 移除這一項；**不開 BUG、不重開工單**；決策日誌記「未驗（使用者略過）」 |
| `A-2：失敗 <說明>`（原有） | 我做了，但沒過 | 照 6.1.x：依內容開 BUG 或重開工單 |

「略過」和「失敗」刻意分開：沒做的驗收不能記成驗過，也不該被當成發現問題。

- **沒附文字**（`U-3：放棄`）：塔台不會再開一題問你新方向（剛放棄的題目換個編號又冒出來，清單永遠清不空）。它清掉工單的 `waiting_user`，在 `todo` 留一則「暫停中，等新方向」，在當次回覆告訴你，等你下次指示。
- **附了文字**（`U-3：放棄 規格還沒定`）：6.3.0 起文字**只當原因**。塔台把它記進決策日誌，不照文字行動；工單維持暫停、不新增待決，有工單時 `todo` 留 `T#### 暫停中（U-n 已放棄：<原因摘要>），等新方向`。原因看起來像指示時也不照做，確認行會多一句「要照原因裡的方向做，請直接下指示」。6.2.x 的塔台會照文字重新對齊，所以這是行為改變。
- **工單狀態都不改**：`BLOCKED` 還是 `BLOCKED`，yolo 斷點的暫停也不會因為放棄就自己繼續。放棄是「不選這些選項」，不是「照預設往下走」。
- **什麼時候算數**：只有冒號後**第一個詞**是「放棄」「略過」時才算，後面的文字是原因（6.2.x 也可以是新方向，6.3.0 起只當原因）。你想用自由文字回答、剛好第一個詞是「放棄」時會被當成放棄；確認行會寫明「U-3 已放棄」，看到不對就重新回答。手打時混用也沒關係：`U-n：略過` 當成放棄、`A-n：放棄` 當成略過。

### 一次好幾題 {#batch}

`U-1、U-3、U-4：放棄 這批不做了`：冒號前列明確的編號，分隔用 `、`、`,` 或全形 `，`，後面附的文字套用到每一題。

- **只用在放棄與略過**：`U-1、U-3：A`（好幾題選同一個選項）不支援，塔台不猜，回一行請你逐題回答。
- **不接受萬用字元與範圍**：`U-*`、`U-1～U-5` 都不收。BAT 的「全部放棄」會在你按下的當下展開成畫面上看得到的編號再送出，免得把你還沒看到、剛寫進來的新題目一起放棄。
- **已經不在清單的編號就略過**，其他照做；確認行會說清楚，例如「U-1、U-3 已放棄；U-4 已不在清單，略過」。
- 同一行可以混 `U` 和 `A`（`U` 讀成放棄、`A` 讀成略過）。批次放棄在決策日誌只記**一筆**，列出全部編號。
- 一題選好幾個選項是[多選](#multi)（`U-4：A、C`），和這裡的一行好幾個編號是兩件事。

### 為什麼把放棄和新方向分開（6.3.0 起） {#dismiss-reason}

6.2.0 的放棄後面可以附「原因或新方向」，塔台得猜那段文字是哪一種：`放棄 規格還沒定` 是原因，`放棄 改做 X` 是指示，`放棄 X 不好，Y 比較好` 兩種都像。猜成指示，塔台就照一句隨口的原因動手；猜成原因，你給的方向就被晾著。6.3.0 把兩件事分開：

| 你要的 | 回什麼 | 塔台會怎麼做 |
|---|---|---|
| 不選任何選項，先停下 | `U-3：放棄` 或 `U-3：放棄 <原因>` | 不套用選項、工單維持暫停；原因照記，不照做 |
| 照新方向做 | `U-3：<新方向>`（自由回答） | 照你的話重新對齊；要改範圍、驗收條件，或屬於不可逆、對外發布的動作，照舊先問你 |

BAT 待辦分頁與原生選單的「其他」送出的就是自由回答；在「其他」以「放棄」開頭時同樣算放棄，後面的文字只當原因。待辦分頁的「其他」與放棄備註照這個分法，要 BAT 0.8.0-pre.8 以上（見[CT 6.3.0 與 BAT 0.8.0-pre.8](#versions-630)）。

## 暫停改開原生選單（6.2.0 起） {#menu}

塔台停下來等你決定時（yolo 斷點、非 yolo 的合併前確認、Worker 的提問轉給你、塔台自己的提問），6.1.x 是印一段文字範本，等你打 `U-n：B`。6.2.0 起改成先照舊寫好待決（`U-n`），**再**開 Claude Code 的原生選單，點一下就好。這沿用既有的 `interactive-prompts`（預設 `on`），沒有新增設定；`*config interactive-prompts off` 就回到 6.1.x 的文字暫停。它只決定問法，要不要把清單寫進檔案仍是 `user_inbox`。

- **題目本身寫完整**：`U-n`、工單、一句話說要決定什麼。選單前面的文字你可能看不到，所以不能只靠前面那段說明。6.3.0 起，同一則回覆處理了你的回答又要開選單時，確認行寫進第一題題目的開頭（「剛才的回答：…」）；確認行超過 4 筆，或自由回答要說明怎麼讀時，這一則不開選單（見[確認行](#confirm)）。6.4.0 起，同一則回覆有的題開選單、有的題要用文字問時，文字問的題也寫進第一題的題目（見[選單題與文字題](#menu-text)）。
- **選項**：推薦項排第一、標「（推薦）」；每個選項的開頭是和待辦清單相同的代號（`A`、`B`…），在 BAT 看到的和在選單看到的對得起來。
- **放棄項**：題目有 1～3 個選項時，最後**一定**多一項「放棄（停下等新方向）」，選了就等於 `U-n：放棄`；剛好 4 個選項時選單已滿，題目結尾提示在「其他」打「放棄」。「其他」可以打自由文字，以「放棄」開頭也算放棄（6.3.0 起後面的文字只當原因）。
- **改用文字的題目**：原生選單最多 4 個選項，超過 4 個的題目改用文字範本；沒有選項的自由回答題也直接用文字問（選單每題要 2～4 個選項，硬湊一個假選項會讓你以為塔台有預設答案）。6.4.0 起，這些題和開選單的題在同一則回覆時，寫進選單第一題的題目（見[選單題與文字題](#menu-text)）。
- **怎麼回答都算數**：選單、在終端打 `U-n：…`、BAT 待辦分頁送出。選單開著時你在待辦分頁按了送出，BAT 會先留著，選單關掉才送到塔台（6.4.0 起搭 BAT 0.8.1-pre.4 以上，改成 BAT 先關掉選單、再送出，見[選單開著時在待辦分頁作答](#menu-handoff)）；如果你已經在選單答過同一題，後到的那行照「編號已結」處理，不會套用兩次。選單開著時 Worker 的完成通知也一樣先留著，不會替你選。
- **按 Esc**：在 Claude Code 裡等於中斷，那一回合直接結束，塔台連說一句話的機會都沒有。所以該筆照留（不算回答、不算放棄），塔台在**你下一次說話後的那一則回覆**開頭提醒哪幾筆的選單被關掉、仍待決，並重列。之後的暫停仍開選單；想改用文字請設 `interactive-prompts off`。6.4.0 起，被關掉的那幾題不再重開選單，提醒改放在確認行之後（見[被關掉的選單不重開](#menu-closed)）。

**什麼時候自動改用文字**（即使 `on`）：

| 情況 | 為什麼 |
|---|---|
| Codex 塔台 | 沒有原生選單 |
| 在 BAT 內，但開工時 `BAT 契約` 不是 `v2`（舊 BAT 或宣告失敗） | 選單開著時，Worker 的通知會打字再按 Enter；只有契約 v2 的 BAT 保證先把通知留著，等選單關掉再送。沒有這個保證，那個 Enter 可能替你選了選項 |
| 不在 BAT 裡的終端 | **不改**，照用選單：沒有 Worker 會自動寫進塔台分頁 |

## 多選（6.3.0 起） {#multi}

有些題目的選項可以同時成立（例如「這次要一起修哪幾個？」），6.2.x 卻只能選一個。6.3.0 起這種題目可以標成多選，一次回好幾個代號。

**什麼時候是多選**：下面三個條件都成立時，塔台才在那一筆寫 `multi: true`（不加引號的 `true`）：

- 是塔台自己或 Worker 的提問。yolo 斷點 A、B-1、B-2、C、E 的暫停**一律單選**：選項是互斥的處置。
- 選項可以同時成立。
- 至少 2 個選項。讀者看到選項少於 2 個的 `multi: true` 時忽略、不報錯。

**怎麼回答**：

| 你回 | 塔台怎麼讀 |
|---|---|
| `U-4：A、C` | 多選 A 和 C |
| `U-4：A,C`、`U-4：A，C`、`U-4：A C`、`U-4：A、C、A` | 一樣是 A 和 C：分隔用 `、`、`,`、全形 `，` 或空白，重複的代號去掉 |
| `U-4：A` | 只有一個代號，就是單選 A |
| `U-4：A 和 C` | 混了別的字，整段當自由回答 |
| 單選題回 `U-3：A、C` | 不是多選題，當自由回答 |

判斷順序是「放棄／略過 → 代號比對 → 自由文字」：拆開後每一個都對得到該題的選項代號（不分大小寫）才算多選。寧可當成你寫的一句話，也不要猜錯成某幾個選項。[批次](#batch)仍只用在放棄與略過，`U-1、U-3：A` 仍不支援。

**多個推薦項**：只有多選題可以有好幾個推薦項，`recommended` 寫成以 `、` 連接的代號（例 `"A、C"`）；每個推薦項都標「（推薦）」、依原順序排在最前面，有一個代號對不到就整個不寫。BAT 會預設勾選推薦項。單選題仍只有一個推薦項。

### 原生選單的複選 {#multi-menu}

多選題開可以複選的選單，**不加放棄項**，題目結尾寫「可複選；要放棄請在「其他」輸入 放棄」。勾選和「其他」一起送出時分三種結果：

| 你送出的 | 塔台怎麼處理 |
|---|---|
| 只有勾選 | 照 `U-n：A、C` 處理 |
| 「其他」以「放棄」開頭 | 放棄；勾選的不套用，只記錄 |
| 「其他」有別的文字 | 整筆當自由回答；勾選的代號與文字一起記錄，塔台照自由回答重新對齊時一起看 |

用文字提問時（Codex 塔台、選項超過 4 個、BAT 契約不是 `v2`、`interactive-prompts: off`），多選題的暫停訊息多一行「可複選：回 `U-n：A、C`」，推薦項照排。

## 確認行：每一筆都回一行（6.3.0 起） {#confirm}

塔台處理你的回答後，在**同一則回覆**為每一個回答各回一行確認，例如 `U-3 已收到：B → 恢復 T0001`；不會只寫一句「已處理完」帶過。你回了好幾筆，就有好幾行。

- **代號依選項的順序**：多個代號依該題選項的順序列出、以 `、` 連接（和 BAT 送出、`recommended` 相同），不依你手打的順序或字母順序。選項依序是 C、A、B（推薦項排在最前面）而你回 `A、C` 時，確認行與決策日誌寫 `C、A`；決策日誌引用你的原文時照原文寫。
- **處理了回答又要開選單時，確認行寫進題目**：同一則回覆既處理了你的回答、又要開下一個選單時，第一題題目的開頭先寫「剛才的回答：」加每一筆的確認（以「；」分隔、寫成一行），再接著寫本題，本題照樣寫完整。題目是開選單一定要寫的內容，選單一開就看得到；按 Esc 之後，Claude Code 列出的「Declined to answer…」也帶題目全文。選單前面的文字照樣可以寫，但不算確認。
- **這一則不開選單**：確認行超過 4 筆，或自由回答需要說明塔台怎麼讀（例如要追問）時，這一則回覆不開選單：確認行照常以文字列出，剩下或新增的待決用文字列出或在回覆結尾重列；下一則回覆再照常開選單。

寫進題目是實機驗收試出來的：6.3.0-pre.1 只回一句總括，pre.2 改了寫法仍沒能讓你在選單開著時看到確認；pre.3 把確認行放進第一題的題目後才補驗通過，正式版照 pre.3 的做法。

## 選單開著時在待辦分頁作答（6.4.0 起） {#menu-handoff}

6.2.0 起塔台暫停時先寫待決、再開 Claude Code 的原生選單，BAT 的待辦分頁同時列出同一題。可是選單開著時，只有終端的選單能可靠作答：在待辦分頁送出的那一行，要嘛被 BAT 留到選單關掉才送，要嘛可能被當成按鍵打進選單。6.4.0 起兩邊都能答：

- **BAT 先關選單、再送出**：你在待辦分頁回答選單裡的某一題時，BAT（0.8.1-pre.4 以上）先替你按 Esc 關掉選單，再把回答以一行 `U-n：…` 送給塔台。塔台把這個 Esc 當成你按的 Esc，接著照常處理那一行。
- **BAT 怎麼知道選單裡有哪幾題**：塔台開選單前，在寫待決的同一次寫入另寫 `menu_open`（選單裡的 `U-n` 與開啟時間）。這是塔台給 BAT 的內部欄位，你不必看、也不必處理；之後任何一次寫入都不再寫它，所以不會殘留。
- **只有選單裡的題才代按 Esc**：待辦分頁回答的題不在選單裡、或沒有開著的選單時，BAT 照舊送出，不按 Esc。權限詢問與 MCP 要求輸入的對話框、Worker 的完成通知，照舊由 BAT 留著，不會替你選。
- **同一題不會套用兩次**：已經在選單答過的題，BAT 又送來同一行時，塔台照「編號不存在或已結」處理。
- **需求對齊的選單不受影響**：開單前的需求對齊提問沒有 `U-n`，塔台不寫 `menu_open`，BAT 照舊把待辦分頁的回答留到選單關掉才送。

### 被關掉的選單不重開 {#menu-closed}

不管 Esc 是你按的還是 BAT 代按的，選單裡的每一題都照留（不算回答、不算放棄）。塔台在下一則回覆：

- 照常處理你的回答，每一筆回一行確認；
- 同一個選單裡沒答的題**不重開選單**，在確認行之後緊接著提醒一次「U-n 的選單已關閉，仍待決，可在待辦分頁或終端回答」（沒有確認行時放在回覆開頭）；
- 這一則有新的待決時，新的那一題照常開選單，**只放新題**；
- 想再用選單問那一題，說「重問 U-n」才重開。

不重開，是因為你從待辦分頁逐題回答時，每重開一次選單，BAT 就得再代按一次 Esc；你已經選擇在待辦分頁作答，選單一直跳回來只會打斷你。沒答的題仍在待辦分頁與回覆結尾的重列裡，不會被忘掉。

### 選單題與文字題在同一則回覆 {#menu-text}

選項超過 4 個、或要你自由回答的題，原生選單放不下，要用文字問。同一則回覆有的題開選單、有的題用文字問時，文字問的題寫進**選單第一題的題目**，選單一開就看得到（選單前面的文字你可能看不到）：

- 順序是「剛才的回答：」確認行 → 被關選單的提醒 → 文字問的題 → 本題；
- 文字問的題每題一段，寫明要決定什麼、選項與回答方式，例 `U-6（工單：—）要先修哪一個；選項 A …／B …；回 U-6：<代號>`；自由回答的題寫「回 `U-n：<文字>`」，多選題加「可複選：回 `U-n：A、C`」；
- 照題目寫的回答就好：在終端或待辦分頁回 `U-n：<代號>` 或 `U-n：<文字>`；
- 文字問的題超過 2 題、或寫不下時，這一則**不開選單**，全部用文字列出，下一則再開。

## 回覆結尾提醒的頻率：`pending_reminder`（6.2.0 起） {#pending-reminder}

6.1.0 起，只要有待決或待執行，塔台每則回覆的最後一行都是 `⏸ 待你決定：…；🙋 待你執行：…`。用的人回饋（GitHub issue #1）：連續好幾則都在處理別的事，那一行卻每則都在，太吵。6.2.0 加了設定 `pending_reminder`：

| 值 | 什麼時候印那一行 |
|---|---|
| `every`（預設） | 有待決時每則回覆都印，和 6.1.x 一樣 |
| `on-change` | 只在這幾個時候印整行：本 session 第一則回覆；清單**多了**新的 `U-n`／`A-n`；你問「目前有什麼待決？」或下 `*sync`（完整列出）；暫停選單被 Esc 關掉後的下一則回覆 |

- **「移除」不算變化**：你回答或放棄一題時，塔台本來就會回一行確認（`U-3 已收到：B`、`U-3 已放棄`），再重列一次是重複。
- **Esc 那一則不受 `on-change` 限制**：選單被你關掉了，那是塔台唯一能告訴你「它還在等」的地方。
- **不受影響的**：狀態檔裡的三個清單照寫、BAT 待辦分頁照常顯示、暫停訊息與選單照開、`user_inbox` 照舊。`pending_reminder` 只管終端那一行。
- **已知限制**：「已經提醒過」是塔台看對話內容判斷的。對話被壓縮之後它不記得前面印過，可能多提醒一次；多一次無害，所以不另外記狀態。

設定方式：`*config pending_reminder on-change --save project`（見[指令參考大全 › `*config`](/reference/commands#config)）。

## 開工宣告：先寫狀態檔，再告訴 BAT {#declare}

塔台本來每次啟動就會用 `--set-role tower` 向 BAT 宣告分頁角色（見[派工 › BAT 派工](./dispatch#bat)）。6.1.0 在同一個呼叫多帶 `--bat-contract 2`，順序是：

1. `_tower-state.md` 還沒有 `bat_contract: 2`（含第一次開工）→ **先寫入**；
2. 帶 `--bat-contract 2` 呼叫 `--set-role tower`；
3. 讀輸出的 `bat-contract:` 與 `hooks:` 兩行。

先寫檔再宣告，是因為 BAT 看到分頁宣告 v2 時會去讀狀態檔，順序反過來就會先讀到一份還不是 v2 的檔。每次 `--set-role` 都要帶這個參數（`*config auto-session` 改模式時的再宣告也一樣），因為 BAT 每次都覆寫這個分頁的宣告，不帶就等於清掉。

狀態面板多一欄 `BAT 契約`：

| `BAT 契約` | 什麼情況 |
|---|---|
| `v2` | BAT 回 `bat-contract: 2` |
| `不支援（BAT 太舊）` | BAT 不支援 v2，或根本不認得這個參數（下一節） |
| `未知（宣告失敗）` | `--set-role` 本身失敗（連線、權杖等），照舊不重試、不擋開工 |
| `略過（非 BAT）` | 不在 BAT 裡，或是 Claude 面板開的塔台 |

CT 只看這一次呼叫的輸出；BAT MCP 雖然也查得到這個分頁的契約版本與 hooks 狀態，CT 不拿那些欄位判斷。

## 舊 BAT 與非 BAT：降級，不會半套 {#fallback}

**舊 BAT：只重送一次。** 太舊的 helper 不認得 `--bat-contract`，會回 exit `1` 加 `Unknown option '--bat-contract'`，而且沒有設定角色。塔台不帶這個參數重送一次，分頁標題與模式照舊可用，本 session 之後都不再帶；開工面板印一行降級提示：

```
⚠️ 這版 BAT 不支援 BAT ↔ CT 契約 v2（需要 BAT ≥ 0.8.0-pre.3）：待辦分頁、通知保護、回合訊息卡不可用；待決事項仍會列在每次回覆的結尾。
```

這和 `--wait-started` 的處理是同一個模式：先送、失敗才降級、只降一次（見[降級鏈](./dispatch#fallback)）。再多試幾次也不會讓舊 BAT 變新，只會把開工拖長。

| 組合 | 會看到什麼 |
|---|---|
| CT 6.1.0＋BAT `>= 0.8.0-pre.3` | 待辦分頁、通知保護、回合訊息卡；面板 `BAT 契約：v2` |

## 兩種 hooks，不是同一件事 {#hooks}

`hooks:` 那一行講的是 **BAT 的 hooks**：BAT 用自己的 claude hooks 知道塔台的 Claude 在做什麼（回合結束、停在對話框、回合訊息卡要的最後一則訊息）。BAT 開的 Claude 分頁會自動加上；但你在 shell 分頁手打 `claude`、在 agent 自訂參數放了 `--settings`、或在 BAT 設定裡關了 BAT MCP 時就沒有。

- BAT 回 `hooks: none (<原因代號>)` 時，塔台在開工面板印一行「這個塔台沒有 BAT hooks：回合訊息卡與對話框保護不可用。」，後面接原因與怎麼修（例如拿掉 `--settings`、改用 BAT「以塔台開啟 Claude」，或安裝 BAT 的 `bat-hooks` plugin）。`hooks: ok …` 與 Codex 的 `hooks: n/a (codex)` 不印，沒問題的事不佔面板。
- 裝了 `bat-hooks` plugin 但它比這版 BAT 舊時，面板提示執行 `claude plugin update bat-hooks@better-agent-terminal`。
- **什麼時候需要 `bat-hooks` plugin**：只有在 BAT 沒辦法替你自動加上 hooks 的時候（上面三種情況）。在塔台問 `/ct-help`〈與 BAT 協作〉可以看到說明。
- **CT 自己的 hooks 是另一件事**，不屬契約 v2。
- **CT 不替你安裝 plugin、不改你的 claude 設定**：面板只告訴你怎麼做，裝不裝由你決定。

## 不想寫進檔案：`user_inbox: off` {#user-inbox}

`*config user_inbox off`（加 `--save project` 保存）之後，塔台就不寫 `awaiting_user`、`user_actions`，退回 6.0.x 的做法：待決只在終端、待執行照舊放 `todo`。`bat_contract`、`ct_version`、`reminders`、工單的 `waiting_user` 照寫，**回覆結尾照印**。典型情境是 `_ct-workorders/` 會公開的專案。它關的是「寫清單」，不是契約 v2：開工宣告照常、`bat_contract` 照寫。6.2.0 起 `inbox_features` 也照寫（能力和要不要寫清單是兩件事），在終端回 `U-n：放棄`、`A-n：略過` 一樣有效；6.3.0 起 `inbox_features` 多了 `multi`，在終端回多選 `U-n：A、C` 一樣有效。6.4.0 起 `inbox_features` 多了 `menu`；`off` 時沒有待決清單，也不寫 `menu_open`。

其他幾個寫法上的約定：

- **隱私**：摘要、標題、選項、指令不寫祕密、權杖、客戶資料或真實個人資料；需要細節就寫「見某工單回報區」。這些欄位會顯示在 BAT 面板上，也跟著 repo 走。
- **時區**：契約 v2 新欄位的時間寫成 `+08:00` 這種帶冒號的時區，既有欄位（`updated_at` 等）維持 `+0800`；兩者都取自系統時間，不手打。
- **筆數上限**：待決、待執行各 20 筆，提醒 10 筆。超過時開工面板多一行提示，不擋流程。
- **寫完自檢多了 v2 的檢查**：6.0.1 起的 `check-frontmatter.py` 對狀態檔另檢查 v2 欄位的型別、編號格式、選項代號、字數與日期，對工單檢查 `waiting_user`（見[字串寫法與寫入後自檢](/deep/principles/files-as-truth#yaml-strings)）。6.2.0 起另檢查 `recommended`（字串、對得到同一筆的選項代號、自由回答時不應有）與 `inbox_features`（字串清單；不認得的值不報錯）。6.3.0 起另檢查 `multi`（存在時要是布林）與多個代號的 `recommended`（該題要是多選、每個代號都對得到）；選項少於 2 個的 `multi: true` 只警告。6.4.0 起另檢查 `menu_open`（形狀、每個 `U-n` 都在 `awaiting_user` 裡、不重複），有 `menu_open` 但 `inbox_features` 沒有 `menu` 時只警告；任何 frontmatter 同一層出現兩次同一個鍵都報 `duplicate-key`，有沒有 PyYAML 都擋（重複的鍵會讓 BAT 整份讀不到，處理方式是合成一個鍵，見[字串寫法與寫入後自檢](/deep/principles/files-as-truth#yaml-strings)）。筆數超過上限是警告（`WARN`），不影響 exit code；其他問題仍是失敗、不得 commit。
