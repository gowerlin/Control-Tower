## 一句話

**放棄就是放棄，新方向另外說；選項能同時成立的題目，可以一次選好幾個。** `U-3：放棄 規格還沒定` 的文字塔台只記下來、不照著做；
要換方向就直接回 `U-3：改做 X`。塔台或 Worker 問的題目選項可以並存時，回 `U-4：A、C`。

---

## 為什麼要把「放棄」和「新方向」分開

6.2.0 的放棄可以附一句話，那句話「是原因也可能是新方向」，塔台照文字重新對齊。用下來發現兩個問題：

- **塔台得猜。** `U-3：放棄 先不做了` 是原因；`U-3：放棄 改用方案 X` 像指示；`U-3：放棄 方案 X 比較好吧` 介於兩者之間。猜錯的代價不對稱：
  把原因當成指示，塔台就動了你沒要它動的東西。
- **選項都不適合時，沒有別的地方可以寫。** BAT 的待辦分頁原本只有選項和放棄，想給新方向的人只好借放棄的備註欄。BAT 自己在分頁加了「其他（自由回答）」，
  新方向有了正式的入口，放棄的備註就不必再身兼兩職。

所以 6.3.0 起：放棄的文字**只是原因**，塔台照記在決策日誌，工單維持暫停，`todo` 留一則「T#### 暫停中（U-3 已放棄：<原因摘要>），等新方向」；
要塔台照新方向做，用自由回答 `U-3：<新方向>`。這是**行為改變**：6.2.x 的塔台還會照放棄後面的文字重新對齊。

**原因看起來像指示時**：塔台仍然不照做，只在確認行後面多一句提醒，例如
「U-3 已放棄 → T0123 維持暫停，等新方向（原因已記錄；要照原因裡的方向做，請直接下指示）」。你再說一次，塔台才動——多一句話，換來不會被誤解。

**「其他」以「放棄」開頭**：在 BAT 待辦分頁或原生選單的「其他」打 `放棄 <原因>`，仍然算放棄，後面的文字同樣只當原因。這是 6.2.0 就有的取捨
（「放棄」是冒號後第一個詞的保留字）；BAT 會在「其他」的輸入框下提示一行。

## 多選：什麼時候會出現

一題要能多選，兩個條件都要成立：

1. **至少 2 個選項。** 1 個選項的多選沒有意義；沒有選項（`options: []`）是自由回答。
2. **題目是塔台或 Worker 的提問**（`tower-question`、`worker-question`），**而且選項可以同時成立**，例如「匯出功能要支援哪些格式」。

**yolo 斷點一律單選。** 斷點 A／B-1／B-2／C／E 的選項是互斥的處置：「接受為 DONE」和「接受為 FAILED」不可能同時成立，「直接合併」和「派合併工單」也只能做一個。
讓這些題目可以複選，只會多出塔台無法執行的組合，所以 CT 從資料層就不寫 `multi`。

塔台寫成多選時，那一筆多一個 `multi: true`。讀者看到選項不到 2 個的 `multi: true` 會忽略它（照單選或自由回答顯示），不會報錯；
`check-frontmatter.py` 只提醒一聲（`v2-multi-ignored`），不算錯誤。

---

## 多選怎麼回答

`U-4：A、C`——冒號後列代號，用 `、`、`,`、全形 `，` 或空白分隔都可以。

- 每一個都得是**這一題**的選項代號（不分大小寫），才算多選；混了別的字（`U-4：A 和 C 都要`）就整段當自由回答，塔台照自由回答處理。
- 重複的代號去掉：手打 `A、A、C` 就是 `A、C`，不會因此變成自由回答。
- 只有一個代號就是單選，跟原本一樣。
- 不是多選的題目回好幾個代號 → 當自由回答（塔台不替你決定該挑哪一個）。
- 判斷順序：先看是不是放棄／略過，再比對代號，最後才是自由文字。多選題一樣可以 `U-4：放棄`。
- 批次和多選不混用：一行好幾個編號仍只用在放棄／略過，`U-1、U-3：A` 照舊不支援。

確認行會列出收到的代號，例如「U-4 已收到：A、C → <處置>」。BAT 送出時固定照選項的順序、用 `、` 連接，所以你從畫面勾的順序不影響結果；pre.2 起塔台的確認行與決策日誌也照選項的順序列（見下方〈pre.2／pre.3 的修正〉）。

**多個推薦項**：只有多選題可以有。`recommended` 寫成 `"A、C"`，每個推薦項的說明都加「（推薦）」，依原本的相對順序排在最前面；BAT 會把它們都標上推薦並預設勾選。
單選題仍只有一個推薦項。塔台寫之前會確認每個代號都對得到，有一個對不到就整個不寫——寧可不推薦，也不要推薦一個不存在的選項。

## 原生選單的複選

塔台暫停改開 Claude Code 原生選單（`interactive-prompts: on`，預設）時，多選題開的是可以複選的選單。和單選題有兩個不同：

**不加「放棄」項。** 單選題 1～3 個選項時，選單最後一定有「放棄（停下等新方向）」。複選選單如果也放這一項，它就成了可以和其他選項一起勾的勾選框，
「放棄＋A」這種答案沒有意思可以解讀。所以多選題的題目結尾改寫「可複選；要放棄請在「其他」輸入 放棄」。

**「其他」和勾選可能同時出現。** 複選選單送回來的可能是「勾了幾項，又在其他打了字」。CT 這樣處理：

| 送回來的 | 塔台怎麼做 | 為什麼 |
|---|---|---|
| 「其他」以「放棄」開頭 | 放棄；勾選的項目**不套用**，只記在決策日誌 | 放棄是明確的停止，比勾選更強；勾過的照記，你的想法不會遺失 |
| 「其他」有別的文字 | 整筆當自由回答，勾選的代號與文字一起記錄，塔台照自由回答重新對齊 | 塔台分不出那段文字是在補充勾選、還是推翻勾選，所以不擅自套用 |
| 只有勾選 | 照 `U-n：<代號>、<代號>` 處理；只勾一項＝單選 | 一般情況 |

選項數的限制和單選題相同：選單一題 2～4 個選項，超過 4 個或沒有選項的題目改用文字。

**用文字提問時**（Codex 塔台、選項超過 4 個、BAT 契約不是 v2、`interactive-prompts: off`），多選題的暫停訊息多一行「可複選：回 `U-n：A、C`」，
提醒你可以一次回好幾個代號。

## pre.2／pre.3 的修正：確認行與代號順序

6.3.0-pre.1 實機驗收時，資料與回答的處理都照規則做到，只有確認行出了問題：使用者一則訊息回答了五筆，塔台處理完只寫一句「已處理完」就開了下一個選單，每一筆被讀成什麼（其中兩筆被當成自由回答）要到下一則回覆才看得到。pre.2 把兩件事寫清楚。

**為什麼確認行每筆一行，而且要讓你在選單裡就看得到。** 確認行的用途是讓你當下看到塔台怎麼讀你的回答，讀錯了可以立刻更正，所以每個回答各一行，不得以「已處理完」之類的總括句代替。難的是同一則回覆還要開選單的時候：Claude Code 的原生選單一開，塔台就要等你作答才能再輸出；你按 Esc，這一回合直接結束。放在選單後面的確認行，要嘛晚一輪才出現，要嘛根本不會出現——你在新選單裡作答時，並不知道上一批回答有幾筆被改讀成自由回答。

**pre.2 的做法與它為什麼不夠。** pre.2 寫的是「確認行先輸出、再開選單」。補驗時這樣仍然失敗：回合的下一步是開選單時，塔台常常直接開選單，選單前一個字都沒寫——它把要說的話寫進了自己的思考，畫面上的 `● … · summary` 看起來像回覆，其實不是（顯不顯示取決於 Claude Code 的設定）。而且選單前面的文字本來就可能被選單蓋住，規範自己也這樣寫。要求確認行放在一個連規範都承認不可靠的位置，等於只靠塔台自覺；再加強措辭也不會明顯變好。

**pre.3 起：確認行寫進選單題目。** 同一則回覆處理了回答又要開選單時，第一題題目開頭先寫「剛才的回答：」加每個回答的確認行（以「；」分隔、寫成一行），再寫本題，例：`剛才的回答：U-3 已收到：C、A → …；U-4 已收到，當成自由回答 → 讀成 C、A。U-5（工單：—）…`。題目是開選單一定要寫的內容，塔台每次都照規範把題目寫完整；選單一開就看得到；你按 Esc 之後，Claude Code 列出的「Declined to answer…」也帶題目全文。選單前的文字照樣可以寫，但不算確認。BAT 不用改：待辦分頁讀的是狀態檔，不是選單題目。

**退路：這一則不開選單。** 確認行超過 4 筆，或自由回答需要說明怎麼判讀（例如要追問）時，題目會被撐得太長，這一則回覆就不開選單：確認行照常以文字列出，剩下或新增的待決用文字列出或在回覆結尾重列；下一則回覆再照常開選單。回合以文字結束時，確認行一直都有逐筆出現，所以這條退路是可靠的。

**為什麼多個代號依 `options` 的順序列。** 推薦項排在最前面，所以選項的順序常常和字母順序不同（例：`C 格式（推薦）`、`A 拼字`、`B 連結`）。BAT 送出時依選項順序寫 `C、A`，`recommended` 也依選項順序寫；如果確認行或決策日誌改成字母順序 `A、C`，同一個回答就有兩種寫法，你會懷疑塔台讀錯了。pre.2 起三處一律照選項的順序，你手打 `U-3：A、C` 也會被確認成「U-3 已收到：C、A → …」。決策日誌〈背景〉引用你打的原文時照原文寫，不受這條限制（6.3.0 正式版補明）。

pre.2 另外補了三件小事：Claude Code 多選選單把勾選的標籤與「其他」的文字以 `, ` 連接送回，塔台以標籤開頭的代號對選項，對不到任何選項的那一段就是「其他」（以前沒寫，寫下來是為了日後回傳形式變了有人察覺）；「預設用繁體中文」明確包含工具呼叫之間的簡短進度句；新 BAT 搭配 6.2.x 塔台時會看到什麼（見下方〈新舊版本搭配〉）。

**沒有改的**：回答「照你的建議」仍當自由回答，不會自動對到推薦項。回答解析刻意只認選項代號與「放棄」「略過」兩個保留字，加入語意片語會讓 BAT 送出的文字和塔台的讀法不再一一對應；當自由回答只是多一輪對齊，不會套錯選項。

## 為什麼還是契約 2：能力旗標 `multi`

和 6.2.0 加推薦項與放棄時一樣：多選是「加上去」的功能，不改任何既有欄位的意思，所以 `bat_contract` 仍是 2，改在狀態檔的能力旗標 `inbox_features` 多一個值 `multi`
（6.3.0 起每次寫 `["recommended", "dismiss", "multi"]`）。`multi` 的意思是「寫這份狀態檔的塔台看得懂 `U-n：A、C`」；BAT 只在看到它時才把 `multi: true` 的題目畫成複選。
這樣新 BAT 搭舊塔台時，不會讓你勾了好幾項、塔台卻讀不懂。

| 6.2.x | 支援多選的版本（≥ 0.8.0-pre.8） | 狀態檔沒有 `multi`，畫面和現在一樣；從「其他」送出的 `U-n：<文字>` 照常處理 |
| 6.2.x | 不支援多選（例 0.8.0-pre.4） | 和 6.2.0 一樣 |

**新 BAT 搭配 6.2.x 塔台**（pre.2 補充，實機看到的）：6.2.x 塔台可能自行在原生選單用複選，但狀態檔不寫 `multi`、BAT 照單選顯示，複選的回答在 6.2.x 會當自由回答（不會錯套選項，要多一輪對齊）；要用複選請把塔台升到 6.3.0。原因是 6.2.x 的暫停段沒有排除複選，塔台把需求對齊「選項可並存就複選」的通則套到了暫停選單；6.3.0 起暫停的多選有明確定義。

支援多選的 BAT 是 **0.8.0-pre.8 以上**（6.3.0 正式版補上）；上表的搭配與新 BAT 搭配 6.2.x 塔台，都在 6.3.0 發佈前的實機驗收看過。

## 常見誤解

- **「放棄後面寫了方案，塔台就會照做」**：6.3.0 起不會。那段文字只是原因；要塔台照做，回 `U-n：<新方向>`。
- **「多選題的『其他』打了字，勾的就沒用了」**：勾的會和文字一起記錄，塔台照自由回答重新對齊時會一起看；只是不會直接套用。
- **「斷點也可以複選」**：不行。斷點的選項是互斥的處置，一律單選。
- **「`U-1、U-3：A` 現在也支援了」**：沒有。多選是一題選好幾個選項；一行好幾個編號仍只用在放棄／略過。
- **「要升級 BAT 才能多選」**：要看到複選畫面才需要（BAT 0.8.0-pre.8 以上）；在任何終端或舊 BAT 的自由回答欄打 `U-n：A、C` 都有效。
- **「多選與確認行還是預覽、還沒在實機跑過」**：6.3.0 起屬正式版；多選、放棄只當原因、確認行寫進選單題目與代號順序都已在 BAT 0.8.0-pre.8 上實機驗證（見〈已知未驗〉）。

## 已知未驗

見 CT `docs/CHANGELOG.md` `[6.3.0]` § Known unverified。預覽期間在 `[6.3.0-pre.1]`～`[6.3.0-pre.3]` 列的項目，6.3.0 發佈前都在 BAT 0.8.0-pre.8 上實機驗過
（另以 BAT 0.8.0-pre.4 搭 CT 6.3.0、CT 6.2.0 搭新 BAT 各跑一個情境），只剩下面兩項：

**已驗證**（逐項見 `[6.3.0]` § 實機驗證）：

- 多選的寫入：每次寫狀態檔都帶 `multi`；只在合適的題目寫 `multi: true`；斷點照單選、選單有「放棄」項
- 多選的解析：去重、三種分隔與空白、混字與單選題多代號當自由回答；一則訊息分好幾行回答好幾筆時逐行處理
- 多個推薦項：都排在前面、都標「（推薦）」，BAT 預設勾選
- 放棄附原因只當原因；原生選單的複選與勾選＋「其他」的三種結果；文字範本的「可複選」一行
- 新舊版本搭配：舊 BAT 照單選顯示、手打 `U-n：A、C` 有效；新 BAT 搭 6.2.0 塔台照單選
- 確認行寫進選單第一題題目、按 Esc 後「Declined to answer…」仍列出全文、長題目換行不截斷；多個代號依選項順序（pre.1 的總括句與 pre.2 的「選單前沒有確認行」都已由 pre.3 的做法補上）

**仍未驗**：

1. Codex 塔台：沒有選單，多選題只走文字範本（「可複選」一行），確認行照常以文字輸出；沒有 Codex 環境，未實機確認
2. 確認行超過 4 筆，或自由回答需要說明時「這一則不開選單」的退路：驗收中處理回答又開選單的回合都只有 2 筆、而且一句寫得完，沒有觸發；
   4 筆時題目的長度與換行也沒有實測（2 筆的題目在終端換成 2 行、完整顯示）
