## 一句話

**塔台推薦哪個選項，寫成資料；不想選任何一個，也有一句話可以說。** 有推薦項時它排第一、說明結尾有「（推薦）」，同一筆另寫 `recommended`，
BAT 據此標記並預設選取；所有選項都不適用時回 `U-n：放棄`（待執行的項目回 `A-n：略過`），一次好幾題也可以。
塔台暫停時也不必再打字：寫好待決後直接開 Claude Code 的原生選單（`interactive-prompts: on`，預設）。

---

## 為什麼要加這兩件事

6.1.0 把塔台的提問搬進檔案以後，在 BAT 的「待辦」分頁回答很方便，但用下來有兩個缺口：

- **看不出推薦。** 在終端裡，塔台的互動選單會把推薦項排第一並標出來；寫進 `awaiting_user` 之後只剩 `options` 一串文字，分頁看不出塔台建議哪一項。
- **沒有退路。** 有時整批不做了、問題已經不合時宜、或要換個方向——所有選項都不適用。以前只能打一段自由文字，塔台還得猜你是不是要放棄。

這兩個需求由 BAT 端提出、BAT 與 CT 雙方使用者核定，CT 在 6.2.0 實作，6.2.0-pre.1 先出規範給 BAT 對照。

## 推薦項：排第一、寫「（推薦）」、再寫一個欄位

三個動作一起做，各有理由：

| 動作 | 給誰看 |
|---|---|
| 推薦項排第一個 | 所有人：終端、舊 BAT、新 BAT 都看得到順序 |
| 說明結尾加「（推薦）」 | 看不到欄位的讀者：終端回覆、舊 BAT、BAT 以外的工具 |
| 同一筆寫 `recommended`（推薦項的代號） | 新 BAT：顯示推薦標記、預設選取那一項 |

**為什麼有了欄位還保留「（推薦）」**：欄位只有新 BAT 讀得懂。拿掉文字，終端與舊 BAT 的使用者就又看不出推薦了。BAT 照原文顯示說明文字，
畫面上同時有標記和「（推薦）」——CT 接受這點重複，換來每種讀者都看得到。

**沒有推薦時兩者都不寫**：兩個選項各有利弊、要你憑偏好決定時，塔台不硬挑一個。自由回答（`options: []`）也不寫 `recommended`。

**塔台自己先對過**：`recommended` 的值要對得到同一筆的某個選項代號（不分大小寫）；對不到就不寫。BAT 那邊遇到對不到的值，當作沒有推薦，不報錯、也不略過這一筆。
`check-frontmatter.py` 會把對不到、型別不對、自由回答卻寫了推薦這三種情況報出來。

## 放棄與略過

### 兩個詞，兩種意思

| 你回 | 意思 | 塔台會怎麼做 |
|---|---|---|
| `U-3：放棄` | 這個決定我不選任何選項 | 移除這一題、不套用任何選項；相關工單**維持暫停** |
| `A-2：略過` | 這件事我不做了 | 移除這一項；**不開 BUG、不重開工單**；決策日誌記「未驗（使用者略過）」 |
| `A-2：失敗 <說明>`（原有） | 我做了，但沒過 | 照 6.1.x：依內容開 BUG 或重開工單 |

「略過」和「失敗」刻意分開：沒做的驗收不能記成驗過，也不該被當成發現問題。決策日誌寫「未驗」，之後看紀錄的人才知道這一項其實沒驗。

手打時容易混用，所以 CT 從寬：`U-n：略過` 當成放棄、`A-n：放棄` 當成略過。BAT 送出時固定用 `U` 放棄、`A` 略過。

### 附一句話，結果不同

- **沒附文字**（`U-3：放棄`）：塔台**不會**再開一題問你新方向。原因很實際：剛放棄的題目換個編號又冒出來，清單永遠清不空，「全部放棄」也就沒有意義。
  塔台改在 `todo` 留一則「T#### 暫停中（U-3 已放棄），等新方向」，在當次回覆告訴你，等你下次指示。
- **附了文字**（`U-3：放棄 改成先做 X`）：塔台照你的話重新對齊。說得明確、沒超出原本範圍就照做；要改範圍、驗收條件，或屬於不可逆、對外發布的動作，照 CT 一貫的規矩先問你。

不論哪一種，**工單狀態都不改**：`BLOCKED` 還是 `BLOCKED`，yolo 斷點的暫停也不會因為放棄就自己繼續。放棄是「不選這些選項」，不是「照預設往下走」。

### 「放棄」什麼時候算數

只有冒號後**第一個詞**是「放棄」「略過」時才算；後面的文字是原因或新方向。這有一個已知的取捨：你想用自由文字回答、剛好第一個詞是「放棄」，
塔台會把它當成放棄。塔台的確認行會寫明「U-3 已放棄」，看到不對就重新回答，照原本「之後更正照新的回答處理」的規則改回來。
選項代號只能是 1～3 個英數字，所以不會和這兩個中文詞撞在一起。

## 批次：一行列好幾個編號

`U-1、U-3、U-4：放棄 這批不做了`——冒號前列明確的編號，分隔用 `、`、`,` 或全形 `，`。後面附的文字套用到每一題。

- **只用在放棄與略過**：`U-1、U-3：A`（好幾題選同一個選項）不支援，塔台不猜，回一行請你逐題回答。
- **不接受萬用字元與範圍**：`U-*`、`U-1～U-5` 都不收。BAT 的「全部放棄」會在你按下的當下展開成畫面上看得到的編號再送出，
  免得把你還沒看到、剛寫進來的新題目一起放棄。
- **已經不在清單的編號就略過**，其他照做；確認行會說清楚，例如「U-1、U-3 已放棄；U-4 已不在清單，略過」。
- 同一行混 `U` 和 `A` 也照處理（`U` 讀成放棄、`A` 讀成略過）。BAT 送出時每區一行，不混。
- 批次放棄在決策日誌只記**一筆**，列出全部編號。

## 為什麼不升契約 3：能力旗標 `inbox_features`

BAT 要知道「這個塔台看不看得懂放棄」，才決定要不要顯示放棄按鈕。最直覺的做法是把契約升到 3，但 CT 沒有這樣做：

- **狀態檔沒辦法替舊 BAT 降版。** 契約版本有兩個來源：開工時的宣告（`--set-role --bat-contract`）可以每個 session 依 BAT 的回應調整；
  狀態檔裡的 `bat_contract` 不行——同一份 `_tower-state.md` 可能同時被本機 BAT、遠端 profile、面板塔台讀，CT 不知道讀的是哪幾個版本。
- **升 3 的代價太大。** 舊 BAT（0.8.0-pre.3）讀到 `bat_contract: 3` 會判成版本不符，把整個待辦分頁藏起來。兩個「加上去」的小功能，
  卻讓舊 BAT 的使用者連既有的待決清單都看不到。
- **相容規則本來就這樣說**：新增欄位不升版，改掉既有欄位的名稱、型別或語意才升。`recommended` 是新的選填鍵，放棄與略過是新的回答寫法，舊寫法完全不變。

所以契約維持 `2`，狀態檔多一個頂層陣列 `inbox_features: ["recommended", "dismiss"]`：

- `dismiss`：寫這份狀態檔的塔台看得懂放棄、略過與批次。BAT 只在有這個值時顯示放棄類的控制項。
- `recommended`：這個塔台會寫 `recommended` 欄位。只是參考——推薦標記看欄位本身就好，寫了就顯示。
- 讀者忽略不認得的值；沒有這個鍵就當空陣列（＝ 6.1.x 的塔台）。以後要再加能力，沿用同一個陣列。

**為什麼只放狀態檔、不加進 `--set-role`**：判斷「CT 看不看得懂這種回答」，看寫這份狀態檔的 CT 版本就夠了，也不必再改一次 helper 的參數與輸出。
`user_inbox: off` 時照樣寫（和 `bat_contract` 一樣：能力和要不要寫清單是兩件事）。

## 暫停改用原生選單

塔台停下來等你決定時（斷點、合併前確認、Worker 的提問轉給你、塔台自己的提問），6.1.x 是印一段文字範本，等你打 `U-n：B`。
6.2.0 起改成先照舊寫好待決（`U-n`），**再**開 Claude Code 的原生選單，點一下就好。

**為什麼沿用 `interactive-prompts`，不另開設定**：這個設定本來就是「選項式提問開關，`off` 時退回純文字」，暫停只是同一件事的另一個場合；
多一個鍵反而要解釋兩個鍵差在哪。它和 `user_inbox`（要不要把清單寫進檔案）是兩件事，本來就分開。代價是沒辦法「需求對齊用選單、暫停用文字」，
CT 判斷這個組合沒什麼人需要，真的有人要再加鍵。`*config interactive-prompts off` 就回到 6.1.x 的文字暫停。

**選單長什麼樣子**：

- 題目本身寫完整——`U-n`、工單、一句話說要決定什麼。選單前面的文字你可能看不到，所以不能只靠前面那段說明。
- 推薦項排第一、標「（推薦）」；每個選項的開頭是和待辦清單相同的代號（`A`、`B`…），在 BAT 看到的和在選單看到的對得起來。
- 題目有 1～3 個選項時，最後**一定**多一項「放棄（停下等新方向）」，選了就等於 `U-n：放棄`；剛好 4 個選項時沒有空位，題目結尾會提示在「其他」打「放棄」。
  「其他」可以打自由文字，以「放棄」開頭也算放棄。
- 原生選單最多 4 個選項；待決最多可以有 6 個選項，超過 4 個的那一題改用文字範本。
- 自由回答的題目（沒有選項）不開選單，直接用文字問（pre.2 起寫明）。
- 怎麼回答都算數：選單、在終端打 `U-n：…`、BAT 待辦分頁送出。回覆結尾的 `⏸ 待你決定` 重列照印（頻率見下方〈回覆結尾的提醒〉）。

**pre.2 修了什麼，為什麼這樣定**（6.2.0-pre.1 實機驗收發現的三處）：

- **放棄項以「題目本身的選項數」為準。** pre.1 寫的是「選項總數 ≤ 3 項時加放棄」，實機上 2 個選項的選單都有放棄、3 個選項的卻沒有——
  「總數」可以讀成「加上放棄之後 ≤ 3」。改成以 `options` 的項數為準（不算選單內建的「其他」）：1～3 項一定加，加上後最多 4 項，剛好塞滿選單；
  4 項時選單已滿，只能請你在「其他」打「放棄」。規則寫成數得出來的條件，就不會有兩種讀法。
- **沒有選項的題目為什麼用文字。** Claude Code 的選單每題要 2～4 個選項。自由回答的題目只剩「放棄」一項，選單根本開不出來；
  硬湊一個假選項又會讓你以為塔台有預設答案。所以直接用文字問，你照 `U-n：<你的話>` 回答。
- **按 Esc 之後為什麼要等下一則才提醒。** Esc 在 Claude Code 裡是「使用者中斷」：工具一被拒絕，這一回合就由 Claude Code 結束，
  塔台連說一句話的機會都沒有——pre.1 條文要求「重列照印」，在這個時間點做不到。所以改成：該筆照留（不算回答、不算放棄），
  塔台在**你下一次說話後的那一則回覆**開頭提醒哪幾筆的選單被關掉、仍待決，並重列。
  按過 Esc 也**不**改變之後的問法，下一題仍開選單：選單或文字由設定決定，行為才可預期、可驗；想改用文字請 `*config interactive-prompts off`。

**什麼時候自動改用文字**（即使 `on`）：

| 情況 | 為什麼 |
|---|---|
| Codex 塔台 | 沒有原生選單 |
| 在 BAT 內，但開工時 `BAT 契約` 不是 `v2`（舊 BAT 或宣告失敗） | 選單開著時，Worker 送來的通知會打字再按 Enter；只有契約 v2 的 BAT 保證會先把通知留著，等選單關掉再送。沒有這個保證，那個 Enter 可能替你選了選項 |
| 非 BAT 終端 | **不改**，照用選單：沒有 Worker 會自動寫進塔台分頁 |

**兩邊都答了怎麼辦**：選單開著時你在 BAT 待辦分頁按了送出，BAT 會先留著，選單關掉才送到塔台。如果你已經在選單裡答過同一題，
那一行就是「已結的編號」，塔台回一行說明並列出還沒決定的編號，不會套用兩次。

## 回覆結尾的提醒：`pending_reminder`（pre.2）

6.1.0 起，只要有待決或待執行，塔台每則回覆的最後一行都是 `⏸ 待你決定：…；🙋 待你執行：…`。用的人回饋（GitHub issue #1）：
連續好幾則都在處理別的事，那一行卻每則都在，太吵。6.2.0-pre.2 加了設定 `pending_reminder`：

| 值 | 什麼時候印那一行 |
|---|---|
| `every`（預設） | 有待決時每則回覆都印，和 6.1.x 一樣 |
| `on-change` | 只在這幾個時候印整行：本 session 第一則回覆；清單**多了**新的 `U-n`／`A-n`；你問「目前有什麼待決？」或下 `*sync`（完整列出）；暫停選單被 Esc 關掉後的下一則回覆 |

**為什麼「移除」不算變化**：你回答或放棄一題時，塔台本來就會回一行確認（`U-3 已收到：B`、`U-3 已放棄`），再重列一次是重複。

**為什麼 Esc 那一則不受 `on-change` 限制**：那是暫停流程的一部分——選單被你關掉了，這是塔台唯一能告訴你「它還在等」的地方。

**不受影響的**：狀態檔裡的三個清單照寫、BAT 待辦分頁照常顯示、暫停訊息與選單照開、`user_inbox` 照舊。`pending_reminder` 只管終端那一行。

**已知限制**：「已經提醒過」是塔台看對話內容判斷的。對話被壓縮（compact）之後它不記得前面印過，可能多提醒一次——多一次無害，所以不另外記狀態。

## 常見誤解

- **「放棄等於選了預設值」**：不是。放棄不套用任何選項，工單維持暫停，等你的新方向。
- **「略過就是驗收通過」**：不是。決策日誌記「未驗（使用者略過）」，不寫成已驗證。
- **「有了 `recommended`，『（推薦）』就該拿掉」**：不拿。終端和舊 BAT 只看得到文字。
- **「`inbox_features` 是新的契約版本」**：不是。契約仍是 2，`inbox_features` 只說這個塔台多會了哪些事；不認得的值一律忽略。
- **「全部放棄會送 `U-*`」**：不會。送出前就展開成明確編號，CT 也不接受萬用字元。
- **「開了原生選單，就只能在選單裡回答」**：不是。待決照樣寫在檔案裡，終端打 `U-n：…` 或 BAT 待辦分頁送出都算數。
- **「`interactive-prompts: off` 會讓待辦分頁看不到」**：不會。它只決定問法（選單或文字）；要不要寫清單是 `user_inbox`。
- **「按了 Esc 就等於放棄」**：不是。Esc 是中斷，那一題照留；要放棄請選「放棄（停下等新方向）」或回 `U-n：放棄`。
- **「`pending_reminder: on-change` 會讓待決消失」**：不會。它只少印終端那一行；清單、待辦分頁、暫停都照舊，問一句「目前有什麼待決？」就完整列出。
- **「Worker 回報 `BLOCKED` 就是斷點 A」**：不是。斷點 A 是通知字串不合法；合法的「需要協助」照收單處理，`BLOCKED`／`FAILED` 計入連續計數（pre.2 標籤改成「連續 FAILED／BLOCKED」）。
- **「推薦項與放棄還是預覽、還沒在實機跑過」**：6.2.0 起屬正式版；推薦項、放棄與略過（含批次）、新舊版本搭配、暫停選單與 Esc、`pending_reminder: on-change` 都已在 BAT 0.8.0-pre.4 的測試版上實機驗證（見〈已知未驗〉）。
