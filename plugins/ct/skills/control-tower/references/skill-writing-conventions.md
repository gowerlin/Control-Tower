# Skill 寫作規範（Meta-guideline）

> 這份文件是「寫 skill 時的規範」，對象是**維護 skill 的人**（未來的你、ct-evolve、或工單派給的 Worker）。
> 不是執行期的行為規則，不影響 Worker 行動。
> 版本：v4.4.0+（併入 GP078 為正式規範）

---

## 棄用條款寫法規範

當 skill 的當前規則與使用者歷史慣例 / Worker memory 中殘留的舊行為衝突時，**不要只寫「嚴禁 X」**——單點的「嚴禁」句式在 LLM 的語意權重中，往往壓不過 memory 中已累積多次的「習慣性允許」訊號。

改用**棄用條款格式**：把「曾允許 → 現棄用」的時間軸對比明文寫出，讓 LLM 讀到時能看到「這條規則經過修訂」的訊號，而不是單純一條沒有脈絡的禁令。

### 根因（GP078）

LLM 的行為訊號強度：

- 單點禁令（「嚴禁 X」）：權重低，易被 memory 中的多次「曾經 X」蓋過
- 對比式棄用條款（「舊版允許 X，新版棄用 X，改用 Y」）：權重高，LLM 看到的是**規則演進**而非單一禁令

這不是「人工多寫字」，而是「在不改變語意的前提下，提高訊號強度」。

### 範本

將下列範本內嵌到 SKILL.md 或對應 reference 的規則段落中：

```markdown
### <規則類別>
- 嚴禁 X（具體行為描述）

> **棄用條款**（v<起始版本>起）：
> 舊版本（例 v<舊版本>）曾允許「X 的變體描述」，自 v<起始版本> 起棄用，由 Y（替代方案）取代。
> 若 Worker memory 中有舊慣例，以本 SKILL.md 為準；若有疑慮，塔台可透過工單 `memory_overrides` 欄位雙重明示。
```

### 實例

```markdown
### Layer 1 保護

- Layer 1 寫入規則見 `data-layer-architecture.md` § 寫入規則（唯一權威定義）

> **棄用條款**（v4.4.0 起）：
> 舊版本（v4.3.x 及更早）曾允許部分工單同步更新 Layer 1，自 v4.4.0 起棄用。
> 若 Worker memory 中有「同步更新 Layer 1」的舊慣例，以權威定義為準；
> 若有疑慮，塔台可透過工單 `memory_overrides` 欄位雙重明示：
> `❌ 「同步更新 Layer 1」→ 本工單處理：見 data-layer-architecture.md § 寫入規則`
```

> ⚠️ 上例僅示範**棄用條款的書寫格式**。Layer 1 的實際範圍、禁止事項與唯一例外
> 一律以 [data-layer-architecture.md](data-layer-architecture.md) § 寫入規則為準，
> 本檔不複述。

### 適用場景

套用棄用條款格式的時機：

- **舊版本的行為被新版本反轉**（例：Layer 1 同步 → Layer 1 唯讀、yolo 可選 → yolo 必須顯式 env）
- **使用者過去曾給過相反指示但現已更新**（memory 可能仍殘留舊指示）
- **牽涉全局記憶的規則變動**（`~/.claude/CLAUDE.md` / auto memory / mem0 有相關條目）
- **連續違規記錄**（GP078 類：規則寫了還是違規，就該升級寫法）

### 不適用場景

不要套用棄用條款格式的情況：

- **首次建立的規則**：無歷史可對比，單點禁令即可。強行補「棄用條款」反而製造虛假歷史
- **極低頻的非核心規則**：寫棄用條款反而增加閱讀成本；保持單點描述更精簡
- **純新功能的規範**（非反轉既有行為）：用標準規則敘述，不需對比

### 效應驗證

寫法升級的判準：若同一條規則在兩次以上 work order 被 Worker 違反，即為 GP078 候選——升級為棄用條款格式。

GP079（Renew-lite + Memory Overrides 模板）為後續工單的防禦機制：在工單元資料用 `memory_overrides` 欄位再強化一次，形成 skill → 工單雙重明示。
