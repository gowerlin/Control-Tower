# 安全匯入引擎（F-17）

> `*import` 內建命令完整規格 — 安全的 local-rules / playbook / config 合併

## 命令語法

| 語法 | 行為 |
|------|------|
| `*import rule` | 互動式新增 local rule → 讀取現有 → 衝突分析 → 確認 → 寫入 |
| `*import playbook` | 互動式新增 playbook → 同上流程 |
| `*import --from <file>` | 從指定文件匯入（可以是草稿檔、其他專案的 `_local-rules.md`） |
| `*import --check` | 查看目前設定狀態（local rules + learnings 概覽） |
| `*import --fix` | 修復格式錯誤（保留內容，自動修正格式） |

## 目標文件對應

| 匯入類型 | 目標文件 | 說明 |
|----------|----------|------|
| `rule` | `_ct-workorders/_local-rules.md` | 專案級自訂規則 |
| `playbook` | `_ct-workorders/_learnings.md` | 專案級學習紀錄 / playbook |
| `--from` | 依來源內容自動判斷 | 若含 `# Local Rules` → rule；若含 `# Learnings` → playbook |

## 核心流程（所有變體共用）

```
1. 讀取目標文件現有內容
   - 不存在 → 記錄「將新建」
   - 存在 → 列出所有區段標題

2. 接收新內容
   - rule / playbook：互動輸入（使用者逐段輸入，空行結束）
   - --from：讀取指定檔案全文

3. 衝突分析
   - 同名區段 → 並排顯示差異 → 詢問處理方式
     [A] 保留舊版（跳過新內容）
     [B] 使用新版（取代舊內容）
     [C] 手動合併（使用者提供合併版本）
   - 無衝突 → 確認後追加

4. 顯示合併計畫摘要
   ┌─────────────────────────────────────┐
   │ 📋 合併計畫                          │
   │ ✅ 新增：N 條區段                    │
   │ ⚠️  衝突：N 條區段（已解決）         │
   │ ⏭️  跳過：N 條區段                   │
   └─────────────────────────────────────┘

5. 使用者確認後才寫入

6. 回報結果：新增 N 條、保留 N 條、跳過 N 條
```

## `*import --check` 行為

列出目前專案的自訂設定狀態：

```
📋 專案設定狀態
├── _local-rules.md：存在（3 條規則）
│   ├── 命名規範
│   ├── 測試規則
│   └── 部署限制
├── _learnings.md：存在（5 條紀錄）
├── _tower-config.yaml：存在
└── 全局 config：~/.claude/control-tower-data/config.yaml（存在）
```

## `*import --fix` 行為

掃描並修復格式問題，保留所有內容：

1. 掃描 `_local-rules.md` 和 `_learnings.md`
2. 檢查格式問題：
   - 區段標題格式不一致（如 `##` vs `###`）
   - 缺少區段分隔（空行）
   - 重複區段標題
   - 編碼問題（亂碼偵測）
3. 列出找到的問題
4. 使用者確認後自動修正
5. 回報：修正 N 處、保留原樣 N 處

## 安全原則（硬限制）

以下 6 條規則為**不可覆寫**的硬限制，任何 `*import` 操作必須遵守：

1. **❌ 絕不直接覆蓋現有文件** — 必須先讀取再合併
2. **❌ 絕不未告知使用者就解決衝突** — 衝突必須經使用者決定
3. **❌ 絕不在確認前寫入** — 所有寫入操作需使用者明確確認
4. **✅ 寫入前必讀現有內容** — 防止資料遺失
5. **✅ 衝突必顯示差異等使用者決定** — 並排顯示 [A]/[B]/[C] 三選一
6. **✅ 寫入後回報「新增/保留/跳過」** — 提供操作結果透明度

## `--from` 來源文件格式

`*import --from <file>` 支援以下來源：

- **專案內文件**：相對路徑如 `docs/rules-draft.md`
- **其他專案的 local-rules**：絕對路徑如 `/path/to/other/_ct-workorders/_local-rules.md`
- **草稿檔**：任意 `.md` 檔案，引擎會嘗試解析區段結構

**解析邏輯**：
1. 讀取來源文件
2. 按 `##` 或 `###` 標題分割區段
3. 每個區段視為一條獨立規則或紀錄
4. 無標題的內容視為單一區段（以檔名為標題）

## 與其他命令的關係

| 命令 | 關係 |
|------|------|
| `*config` | `*import` 管理 rules/learnings，`*config` 管理 runtime 設定 |
| `*evolve` | `*evolve` 自動產出學習紀錄 → `*import` 可從其他專案匯入學習紀錄 |
| `*fieldguide` | FIELDGUIDE 產出的 playbook → 可用 `*import --from` 匯入 |
