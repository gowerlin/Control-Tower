# 微應用 / Mono-repo 模式

## 單一塔台管多子專案

啟動時告知結構：

```
/control-tower
我的專案是 mono-repo：
- app-a/：[功能簡述]，有獨立 .git
- app-b/：[功能簡述]，有獨立 .git
- shared/：[共用模組]
```

塔台額外職責：

1. **工單標記子專案**：元資料中標注「目標子專案：app-a」
2. **跨專案影響偵測**：改 shared/ 時提醒兩邊測試
3. **文件歸屬建議**：共用文件放 parent/docs/，子專案特有的放各自目錄

## 目錄結構建議

```
parent-dir/
├── _ct-workorders/          ← 工單統一管理
├── docs/                    ← BMad 共用文件
│   ├── project-context.md
│   ├── prd.md
│   └── sprint-status.yaml
├── app-a/
│   ├── .git/
│   └── docs/                ← app-a 專屬文件
└── app-b/
    ├── .git/
    └── docs/                ← app-b 專屬文件
```

## 文件同步衛生

塔台在以下時機提醒檢查文件與程式碼一致性：
- 每個 Story 完成後：「本次改動是否影響 project-context.md 或 architecture.md？」
- Sprint 結束時：派發「文件同步檢查」工單
- 發現回報的程式碼結構與文件描述不符時：主動標記 ⚠

## 跨子專案重複需求

```
同一需求需要在多個子專案實作？
├─ 邏輯完全相同
│   └─ 抽到 shared/ 作為共用模組
│
├─ 規則相同但實作因技術棧不同
│   └─ 先做一、後參照模式
│      1. 先派 app-a 工單（含 spec + 實作 + 測試）
│      2. 完成後派 app-b 工單，附上：
│         - 參照實作路徑
│         - 一致性要求
│         - 可變範圍
│         - 測試案例（必須覆蓋相同場景）
│
└─ 規則不同
    └─ 各自獨立，分別派發互不相依的工單
```

## 多專案協調

管理多個相關專案（前後端分離、微服務）時：
- 追蹤每個專案的獨立進度
- A 專案影響 B 時，主動提醒同步設計文件
- 派發工單時附上「需參照其他專案的檔案路徑」
