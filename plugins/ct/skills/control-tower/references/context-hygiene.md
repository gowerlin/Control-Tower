# Context 衛生管理

## Session 建議規則

| 觸發條件 | Session 建議 | 原因 |
|----------|-------------|------|
| 全新任務 | 🆕 新 Session | 需要乾淨 Context Window |
| 對話超過 5 輪 | 🆕 新 Session | 累積太多上下文 |
| 改 A 壞 B | 🆕 新 Session | 連鎖錯誤，假設已偏移 |
| 任務切換 | 🆕 新 Session | 從開發切到 review |
| AI 在繞圈 | 🆕 新 Session | 需要重置 |
| 同一問題修 3+ 次 | 🆕 新 Session | 大量 debug 汙染 |
| 審查類工單 | 🆕 新 Session | 避免確認偏誤 |
| 小修補 / 接續 | 🔄 原 Session | 上下文仍相關 |
| 同一 story 後續 | 🔄 原 Session | context 有連續性 |

建議開新 session 時提醒：
```
⚠ 建議開新 Session 執行下一張工單
原因：[具體原因]
請先在當前 sub-session 確認：
  1. 工單回報區已填寫完成
  2. 程式碼已 commit（或 stash）
  3. sprint-status.yaml 已更新
確認後，回報工單編號即可。
```

## 進度追蹤

### 進度表格式

```
## Sprint 進度
| Story | 工單 | 狀態 | 卡點 | 下一步 |
|-------|------|------|------|--------|
```

每次處理工單回報時自動更新。

### 狀態同步

塔台進度表是**記憶狀態**（context window），工單檔案是**事實狀態**（磁碟）。

**觸發同步**：使用者說 `重新同步` / `sync` / `檢查進度` / `進度不對`

**同步流程**：
1. Glob 掃描 `_ct-workorders/T*.md`
2. 讀取每張工單元資料
3. 交叉比對三方（塔台記憶 / 工單檔案 / yaml）
4. 產出差異報告
5. 以工單檔案為 truth 修正

**同步報告格式**：
```
🔄 同步檢查完成

差異發現：
| 工單 | 塔台記憶 | 工單檔案 | yaml | 修正動作 |
|------|----------|----------|------|----------|

已修正 N 項差異。
```
