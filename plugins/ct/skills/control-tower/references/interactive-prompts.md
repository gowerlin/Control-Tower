# 互動式選項提問規範

> 減少使用者打字量，讓 AI 展示對需求的預判供使用者快速確認或修正。

## 適用場景

| 場景 | 是否強制 | 說明 |
|------|---------|------|
| 需求對齊協議（步驟 2「提問」） | **強制** | 每個問題必須附帶選項 |
| 問題分診 | AI 判斷 | 問題類型明確時適合 |
| 工單類型選擇 | AI 判斷 | 預定義選項較多時適合 |
| 優先級確認 | AI 判斷 | 選項有限且明確 |
| 其他互動 | AI 判斷 | 評估是否能減少來回 |

> 當 `*config interactive-prompts` 設為 `off` 時，所有場景皆退回純文字提問。

## 選項格式規範

### 文字條列格式（通用 fallback）

```
問題描述？

[A] 選項一的描述
[B] 選項二的描述
[C] 選項三的描述
[D] 其他：________
```

### 複選格式

```
以下哪些需要處理？（可多選，例如 AC）

[A] 項目一
[B] 項目二
[C] 項目三
[D] 以上皆是
[E] 其他：________
```

### 確認格式（是/否 + 備註）

```
我的理解是：⋯⋯
這樣對嗎？

[A] 對，繼續
[B] 大致對，但需要修正：________
[C] 不對，我的意思是：________
```

## 選項內容規則

1. **AI 預判選項**：根據上下文動態推測最可能的答案（排在前面）
2. **預定義選項**：適用時加入（如工單類型：`feature` / `bugfix` / `refactor` / `analysis`）
3. **兜底選項**：最後一項**必須**為自由輸入（「其他：________」或「補充：________」）
4. **選項數量**：3-6 個為佳，超過 6 個考慮分組或分步

## 單選 vs 複選判斷

| 情境 | 建議類型 | 判斷依據 |
|------|---------|---------|
| 工單類型 | 單選 | 互斥選項 |
| 優先級 | 單選 | 互斥選項 |
| 影響範圍 | 複選 | 可能多個同時適用 |
| 需求特性 | 複選 | 多個面向並存 |
| 是否確認 | 單選 | 二元決策 |

**判斷原則**：選項間互斥 → 單選；選項間可並存 → 複選。

## 環境工具偵測

### 偵測優先順序

1. **環境內建機制**：檢查當前 AI 工具是否有原生選項 UI
   - Claude Code：`AskUserQuestion` 工具（如支援選項參數時使用）
   - 其他工具：檢查對應的互動 API
2. **文字條列 fallback**：無內建機制時使用上述格式

### Claude Code 範例

```
# 若 AskUserQuestion 支援選項：
AskUserQuestion(
  question="這個任務的範圍是？",
  options=["僅修改後端 API", "前後端都要改", "只改資料庫", "其他"]
)

# 若不支援選項（fallback）：
以文字呈現：
「這個任務的範圍是？
[A] 僅修改後端 API
[B] 前後端都要改
[C] 只改資料庫
[D] 其他：________」
```

## 場景範例

### 需求對齊 — 新功能討論

```
👤 使用者：「我想加一個通知功能」

🗼 塔台：
了解，讓我釐清幾個面向：

1. 通知的觸發方式？
   [A] 系統事件自動觸發（如訂單狀態變更）
   [B] 使用者手動發送
   [C] 定時排程
   [D] 以上皆有
   [E] 其他：________

2. 通知管道？（可多選，例如 AB）
   [A] Email
   [B] 站內通知（Web）
   [C] Push Notification（手機）
   [D] LINE / Slack / Teams
   [E] 其他：________

3. 這個功能的優先級？
   [A] 急 — 本 Sprint 要完成
   [B] 重要但不急 — 下個 Sprint
   [C] 想先評估可行性
   [D] 其他：________
```

### 問題分診 — Sub-session 回報問題

```
🗼 塔台：
這個問題看起來可能是以下哪一類？

[A] 設計層面 — 需求理解有偏差，需要重新對齊
[B] 實作層面 — 知道要做什麼，但技術實現遇到困難
[C] 環境層面 — 開發環境、相依套件、權限等問題
[D] 不確定，需要更多分析
```

### 工單類型選擇

```
🗼 塔台：
根據討論，這張工單的類型應該是？

[A] feature — 新功能開發
[B] bugfix — 修復已知問題
[C] refactor — 重構改善
[D] analysis — 分析調查（先釐清再決定）
[E] other：________
```
