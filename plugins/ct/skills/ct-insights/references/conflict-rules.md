# 原則衝突偵測規則

> 掃描工單歷史和決策日誌，偵測 Control Tower 原則的違反和衝突。
> 每項衝突有明確的偵測信號和嚴重度分級。

---

## 衝突偵測表

| # | 原則 | 衝突信號 | 嚴重度 | 偵測方式 |
|---|------|---------|--------|---------|
| C1 | 塔台不讀程式碼 | 決策日誌/工單中出現 Tower 分析程式碼的痕跡 | 🔴 嚴重 | 掃描 `_decision-log.md` 和 `_tower-state.md` |
| C2 | 工單檔案是事實來源 | yaml 狀態與工單檔案不一致 | 🟡 中等 | 引用 `/ct-status sync` 差異記錄 |
| C3 | 熔斷規則 | sub-session 連續 >3 輪試錯但未回報 BLOCKED | 🟡 中等 | 掃描工單互動紀錄中的熔斷事件 |
| C4 | 品質閘門 | 審查工單有 CRITICAL 發現但後續無修正工單 | 🔴 嚴重 | 追蹤審查→修正工單鏈 |
| C5 | 本地優先 | 同一張工單同時涉及本地修改和 CICD 部署 | 🟡 中等 | 掃描工單任務指令的範圍 |
| C6 | 一次追一條線 | 同一時段（30 分鐘內）有 3+ 張工單同時 IN_PROGRESS | 🔴 嚴重 | 掃描工單的時間戳重疊 |

## 偵測細節

### C1 塔台不讀程式碼（🔴 嚴重）

**偵測方式**：
1. 掃描 `_decision-log.md`：尋找 Tower session 中分析原始碼的記錄
2. 掃描 `_tower-state.md`：檢查是否有違憲標記
3. 掃描工單回報區：Tower 是否在回報中引用了具體程式碼行

**判定條件**：Tower session 中出現以下痕跡之一
- 決策日誌記錄中包含程式碼分析
- 使用者在 Tower 中貼了程式碼且 Tower 回應了分析結果

**改善建議**：派分析工單給 sub-session，Tower 只看結論

### C2 工單檔案是事實來源（🟡 中等）

**偵測方式**：
1. 讀取 `/ct-status sync` 或 `*sync` 的歷史差異記錄
2. 統計 yaml 與工單檔案不一致的次數

**判定條件**：sync 修正記錄 ≥3 次

**改善建議**：確認 sub-session 使用 `/ct-exec`（會自動更新 yaml）

### C3 熔斷規則（🟡 中等）

**偵測方式**：
1. 掃描所有工單的互動紀錄
2. 尋找熔斷計數器觸發事件
3. 檢查觸發後使用者是否選了 [C]（繼續）而非 [A]（收尾）

**判定條件**：sub-session 連續 >3 輪試錯未回報 BLOCKED，或多次選擇 [C] 忽略熔斷

**改善建議**：信任熔斷機制，選 [A] 收尾讓 Tower 重新規劃

### C4 品質閘門（🔴 嚴重）

**偵測方式**：
1. 辨識審查類工單（任務名稱含「審查」「review」「code review」）
2. 讀取審查工單的回報區，尋找 CRITICAL / HIGH 等級發現
3. 檢查審查工單完成後，是否存在對應的修正工單

**判定條件**：審查工單有 CRITICAL 發現，但後續 5 張工單內無修正工單

**改善建議**：審查發現 CRITICAL 後必須立刻派修正工單

### C5 本地優先（🟡 中等）

**偵測方式**：
1. 掃描工單任務指令
2. 同一張工單中是否同時涉及本地程式碼修改和 CICD/部署操作

**判定條件**：工單任務指令同時包含「修改程式碼」和「部署/CICD」步驟

**改善建議**：拆分為兩張工單：先修改程式碼、確認本地通過，再處理 CICD

### C6 一次追一條線（🔴 嚴重）

**偵測方式**：
1. 讀取所有工單的開始時間和完成時間
2. 建立時間線，偵測重疊的 IN_PROGRESS 工單

**判定條件**：同一 30 分鐘時段內有 3+ 張工單同時為 IN_PROGRESS 狀態

**改善建議**：逐一解決，一次只追一條線

## 報告輸出格式

```
## ⚠️ 原則衝突

  🔴 C1 塔台不讀程式碼
     發生 2 次（2026-03-20, 2026-03-28）
     佐證：D005 決策日誌記錄、T0012 互動紀錄
     建議：派分析工單給 sub-session

  🔴 C6 一次追一條線
     發生 1 次（2026-03-25）
     佐證：T0008, T0009, T0010 同時 IN_PROGRESS
     建議：逐一解決

  🟡 C2 工單檔案是事實來源
     sync 修正 4 次
     建議：確認使用 /ct-exec 自動更新
```

## 嚴重度對照

| 嚴重度 | 意義 | 報告中的行為 |
|--------|------|-------------|
| 🔴 嚴重 | 核心原則違反，可能導致工作流程失效 | 列在報告最上方，標紅高亮 |
| 🟡 中等 | 次要原則偏離，累積可能導致問題 | 列在嚴重之後，建議改善 |
