# 報告格式範本

> ct-insights 的報告結構定義，涵蓋三層作用域。

---

## 使用統計（數據面板）

所有層級的報告都以數據面板開頭：

```
╔══════════════════════════════════════════════════════════╗
║  📊 Control Tower Insights — [專案名/全局/本次 Session]  ║
╠══════════════════════════════════════════════════════════╣
║  分析期間：[起始日] ~ [結束日]（N 天）                    ║
║  工單總數：N 張                                         ║
║  完成率：N%（N/N）                                      ║
║  平均工單耗時：N 分鐘                                   ║
║  塔台 session 數：N                                     ║
║  塔台重啟次數：N（原因分布）                             ║
╚══════════════════════════════════════════════════════════╝
```

## 工單健康度（5 項指標）

| 指標 | 計算方式 | 健康基準 | 說明 |
|------|---------|---------|------|
| **完成率** | DONE / 總數 | ≥80% | 低於此值可能是工單拆分過大 |
| **熔斷率** | BLOCKED / 總數 | ≤20% | 高於此值可能是前置分析不足 |
| **估時偏差** | \|實際-預估\|/預估 | ≤50% | 高於此值需要校準估時 |
| **首次完成率** | 非 PARTIAL 非 FAILED / 總數 | ≥60% | 低於此值可能是驗收條件不清 |
| **平均回報品質** | 回報區有結構化內容的比例 | ≥80% | 低於此值可能是 sub-session 沒收尾 |

**計算說明**：

- **完成率**：`count(status=DONE) / count(all)` × 100%
- **熔斷率**：`count(status=BLOCKED) / count(all)` × 100%
- **估時偏差**：對有預估時間的工單，計算 `avg(|actual - estimated| / estimated)` × 100%
  - 無預估時間的工單不計入
- **首次完成率**：`count(status=DONE AND never_been_PARTIAL_or_FAILED) / count(all)` × 100%
- **平均回報品質**：`count(report_has_structured_content) / count(status=DONE)` × 100%
  - 結構化內容判定：產出摘要非空（>20 字）、含檔案清單或變更描述

**健康度面板**：

```
## 🏥 工單健康度

  完成率       ████████░░  78%  ✅ 健康（≥80%）
  熔斷率       ██░░░░░░░░  15%  ✅ 健康（≤20%）
  估時偏差     ██████░░░░  +62% ⚠️ 偏高（≤50%）
  首次完成率   ██████░░░░  65%  ✅ 健康（≥60%）
  回報品質     █████████░  87%  ✅ 健康（≥80%）
```

## 完整報告結構（Project / Global）

```
═══════════════════════════════════════════════
  CT-INSIGHTS 使用模式分析報告
  範圍：[專案名 / 全局]
  期間：[起始日] ~ [結束日]
  資料：N 張工單 / N 個決策 / N 筆學習
═══════════════════════════════════════════════

## 📊 使用統計
  （數據面板）

## 🏥 工單健康度
  （5 項指標 + 進度條 + 基準對照）

## ✅ 做得好的地方
  （偵測到的好模式，附具體工單編號佐證）
  （來源：analysis-rules.md G1-G5）

## ❌ 需要改善的地方
  （偵測到的壞模式，附具體工單編號佐證）
  （來源：analysis-rules.md B1-B6）

## ⚠️ 原則衝突
  （偵測到的原則違反，按嚴重度排序）
  （來源：conflict-rules.md C1-C6）

## 📈 趨勢分析
  （完成率/估時偏差/熔斷率隨時間的變化）
  （僅 global 層：跨專案比較）

## 🎯 改善建議
  （優先級排序的具體建議）
  （含可直接貼的 *config / _local-rules.md 規則）

## 🧠 學習記憶庫健康度
  （活躍模式數 / 廢棄模式數 / 置信度分布）
  （全局層：晉升率 / 降級率）

═══════════════════════════════════════════════
```

## 改善建議格式

```
## 🎯 改善建議

### 優先級 1：[標題]
[觀察描述，附數據和工單編號]
建議：[具體可操作的改善方案]

### 優先級 2：[標題]
[觀察描述]
建議：[具體可操作的改善方案]

### 建議新增的塔台規則
基於你的使用模式，以下規則可能有幫助：

  *config [option] [value] --save project
  # [規則說明]

  # 建議加入 _local-rules.md：
  「[具體規則文字]」
```

## 學習記憶庫健康度格式

```
## 🧠 學習記憶庫健康度

  活躍模式：N 個（⭐N / 🟢N / 🟡N / 🔵N）
  廢棄模式：N 個（❌ 標記）
  休眠模式：N 個（連續 3 專案未觸發）
  置信度分布：[分布圖]

  全局層（僅 global 報告）：
  晉升率：N%（project → global）
  降級率：N%（降級或廢棄）
  Playbook：N 個（常用 N / 未使用 N）
```

## Beginner 模式額外區段

如果 `experience-level: beginner`，報告末尾額外加入新手進度：

```
## 🎓 新手進度
  教學關卡完成度：N/5
  違規糾正次數：貼程式碼(N)、模糊回報(N)、貼 log(N)
  最近 3 張工單違規：N 次
  畢業建議：[再完成 N 張無違規工單即可升級到 standard / 已可畢業 / 保持練習]
```

**資料來源**：`_tower-state.md` 的「教學進度」區段

## Session 層精簡報告格式（`*insights`）

在 Tower session 內嵌入對話流的精簡格式：

```
📊 本輪 Tower Session Insights

  工單：派發 N 張 / 完成 N 張 / 進行中 N 張
  決策糾正：N 次（D###：[摘要]）
  互動模式：✅ 正常 / ⚠️ [偵測到的問題]
  context 健康度：🟢/🟡/🔴 第 N 輪，[建議]

  💡 建議：
  - [具體可操作的建議 1]
  - [具體可操作的建議 2]
```

**Session 層分析維度**：

| 維度 | 說明 |
|------|------|
| **本輪工單派發** | 派了幾張？完成了幾張？有沒有膨脹的？ |
| **本輪決策品質** | 有沒有被使用者糾正？糾正了什麼？ |
| **本輪互動模式** | 使用者有沒有在 Tower 裡做 sub-session 的事？ |
| **本輪原則衝突** | 塔台有沒有越權？使用者有沒有貼程式碼/log？ |
| **context 健康度** | 目前對話輪數、估計 context 使用率、是否該 /clear |

## Global 層額外區段

Global 報告在「趨勢分析」和「學習健康度」之間加入跨專案比較：

```
## 🌐 跨專案比較

  | 專案 | 工單數 | 完成率 | 熔斷率 | 估時偏差 | 特色模式 |
  |------|--------|--------|--------|---------|---------|
  | project-a | 23 | 78% | 15% | +62% | G5 漸進拆分 |
  | project-b | 45 | 85% | 8%  | +25% | G1 排除法 |
  | project-c | 12 | 67% | 25% | +87% | B4 工單膨脹 |

  最佳實踐：project-b 的估時偏差最低，其工單平均粒度為 25min
  需關注：project-c 的熔斷率偏高，建議加強前置分析
```
